# AI 自主学习教练系统 · 教育理念评审与优化建议

> 评审对象：`education/docs/教育IDE_需求文档_可参赛版.md`（v5.2）与 `education/goai-preliminary-submission/02-项目方案书.md`（v1.6）
>
> 评审视角：以教育理念（自我调节学习、动机理论、学习科学、形成性评价）审视方案的真实性、专业度与可补充之处

---

## 1. 总体判断：是真实的场景方案，且教育理念底子扎实

这不是"为 AI 而 AI"的方案，痛点采集、闭环设计都来自真实自学场景：

- 目标难落地（有愿望、无路径）
- 启动难持续（知道要学、按时开始难）
- 线下学习不可见（纸质作业、试卷在 App 外）
- 受挫支持失当（要么给答案、要么给鸡汤）
- 计划不会生长（静态计划无法随状态调整）

更难得的是，方案暗合多条主流教育理论，而非停留在"智能"噱头上。下表是方案设计与教育理念的对应关系（**建议在文档中显式标注**，评委为教育背景时一目了然）：

| 方案设计 | 对应的教育理念 |
|---|---|
| 目标确认 → 计划 → 执行 → 反馈 → 反思 → 调整闭环 | **自我调节学习 SRL**（Zimmerman 前瞻 / 表现 / 自我反思三阶段） |
| 学生可拒绝、可改期、选择权优先 | **自我决定理论 SDT**（自主感 / 胜任感 / 关联感） |
| 不直接给答案，提示 → 分步 → 策略 | **最近发展区 ZPD + 脚手架理论**（Vygotsky） |
| 连续受阻 → 降阶、缩时、换表征 | **认知负荷理论 + 掌握学习**（Bloom） |
| 证据不足不下结论、可更正 | **形成性评价**（Black & Wiliam）与 **成长型思维**（Dweck） |
| 信心自评、不贴标签 | **自我效能感**（Bandura） |

---

## 2. 为什么说它"真实"（方案亮点）

1. **纸质主学 + 短时屏幕**：贴合中国学生真实状态——作业、教辅、卷子本就是主战场。方案明确拒绝"内置题库刷屏"，并做了屏时预算，比大多数教育 AI 产品诚实。
2. **材料盘点**（已有卷子/教辅/页码任务）：中国家庭教辅存量巨大，"先用现有材料，再考虑补购"的顾问式建议真实且得体。
3. **状态建模的克制**：事实/自评/推断分层、短有效期、缺失≠0 分、趋势≠因果、"学生更正优先于系统推断"——避免了教育 AI 最常见的"从行为推断情绪/人格"的坑。
4. **主动但不打扰**：默认每日主动消息 ≤ 2 次；"稍后 / 暂停 / 静默 / 免打扰"立即生效，符合真实青少年的耐受度。

## 3. 需要质疑 / 理想化的部分（评委可能挑刺的点）

### 3.1 "半年数学提升 20 分"是结果目标，不是学习目标

教育理念上应引导**可验证的过程目标**（"4 周内函数图像转换错因率下降"），分数只是副产品。

**建议**：采用双目标结构 —— 成果目标 + 过程目标，并在初始化时教学生把目标改写成可验证形式（"怎么知道做到了"）。

> 注：需求文档 §7.1 已有目标复述确认对话（"我理解为半年内提升数学成绩 20 分…"），说明方案已在做目标具体化；缺的是把"分数结果"改写成"可验证过程证据"的显式步骤。

### 3.2 目标用户过宽，叙事不聚焦

方案书 §1.2 用户表覆盖初中生/高中生/大学生/成人四类，但同一节已声明"Demo 与模拟数据以初二学员'小林'为示例"（§8 演示也以初中生为例）——**主叙事其实已聚焦初中生**；问题是目标群体声明（"初中及以上全学段"）仍偏宽，且四类用户的价值主张表让评委误以为都要覆盖。

**建议**：保留小林主叙事不变，把 §1.2 用户表改为"主场景（初中生）+ 延伸场景（高中/大学/成人）"两栏结构，避免"哪个都不深"的观感。

### 3.3 拍照取证的现实约束

学生是否愿意拍、拍得是否清晰、家长是否允许用手机、OCR 准确率——这些现实约束成立，但"方案自己也承认'拍照错因诊断入库未实现'"这一表述**已过时**：它只反映了方案书 §10 实现现状表（v1.6）与 SPEC 的文字状态，未核对实现仓库 `cn-codex-edu` 的实际代码：

- `src-tauri/src/ocr/mod.rs`：真实 PP-OCRv5 mobile OCR（onnxruntime + det/rec 模型 + vocab），`ocr_image` 工具已注册（`tool_executor.rs`），图片附件走本地 OCR 提取文本（`agent.rs`）；
- `mobile-web/src/learningCapture.ts`：端侧帧质量筛选（清晰度/抖动/反光/边缘完整度/透视偏差）→ 最佳关键帧 → **学生确认后的 OCR 文本才入库**（`ExamCapturePayload`）；`mobile_server.rs` 已提供 `/exam-capture` 接收端。

因此准确的现状是：**拍照取证（拍照 → 帧筛选 → OCR → 确认 → 入库）已实现**；"错因归类写证据"依赖学科包错因分类（junior-math），这才是真正的下一步。

**建议（修正）**：5 分钟演示应**直接展示真实拍照 → OCR → 学生确认 → 入库链路**（本地 PP-OCRv5，无需联网），而非降级为"选择题卡点"；若担心现场翻车，可准备一张预拍的清晰作业照片作为回退，而不是砍掉拍照能力。

### 3.4 "学习态度精神"是自造词，学术上不严谨

**建议**：改用教育学标准词汇："**自我调节学习能力**（目标设定、时间管理、自我监控、反思）与**学业自我效能**"。

> 注：该词仅出现在方案书 §1.2/§2A 的"双主线建模"叙事中（SPEC v1.5 起），需求文档本身用的是标准词汇（目标计划/执行投入/监控反思/动机情感），修改成本集中在方案书与 SPEC。

### 3.5 缺少"逐步放手"的具体机制（最关键的短板）

需求文档 §7.7 已有一张"系统脚手架 | 逐步放手方式"表（目标管理/时间管理/自我监控/反思/策略调整五条），方向正确；但全是定性描述，**没有说明系统何时、依据什么信号降低介入**（例如"连续 N 周执行稳定 + 自评信心上升 → 提醒降频一半"），也没有进入 Demo 脚本。在 SRL 理念下，这是最能证明"不是让学生依赖 AI"的点，目前仍是抽象承诺。

## 4. 建议补充的地方（按优先级）

### 🔴 高优先级（直接影响说服力）

#### 4.1 显式化"放手"机制（Fading）

把 §7.7 的定性放手表升级为**量化触发 + 可演示、可评测**的设计，例如：

```text
连续 3 周执行稳定且自评信心上升
  → 主动提醒降频一半
  → 提供"教练模式 / 自助模式"切换
  → 周回顾改为学生主导、AI 只做证据摘要
  → 学生主动决策次数进入成长报告
```

#### 4.2 引入学习科学的策略库（Dunlosky 2013 高有效性技术）

需求文档 §10 已有 5 类干预场景的策略（回退基础/换示例/减少题量/请求教师帮助、改时间/缩短到 10 分钟/暂停/关闭提醒、增加示范/拆小步骤/低风险练习、轻量询问/静默、休息建议/减负/改期/联系成年人），§5.6 决策矩阵还有"做 3 题检查 / 讲给 AI 听 / 暂不检查"——"讲给 AI 听"就是**检索练习**的雏形。缺的不是策略数量，而是按学习科学命名的正式任务类型：

| 策略 | 落地方式 |
|---|---|
| **检索练习** | "讲给 AI 听"（已有雏形，应上升为正式任务类型） |
| **交错练习** | 混合不同知识点的小题组，而非同质刷题 |
| **间隔复习** | 知识证据"需巩固"后，在 2 / 7 / 14 天自动安排轻量复习任务 |

这让"动态计划"有科学抓手，而不是凭规则拍脑袋。

#### 4.3 补充教育效果评测维度

需求文档 §2.3 已有"自主能力成长：周期回顾中呈现目标复盘、计划调整和学习策略的学生自主决策证据"，方向正确；方案书 §11 仍偏产品功能指标。缺的是**可量化、可前后测的教育指标**：

- 错因再犯率变化（同一知识点两次任务间）
- 4–6 周 SRL 量表前后测（如 MSLQ 自主学习分量表）
- 计划调整中学生主动决策次数（自主性证据）
- 4 周留存率 / 每周主动反馈次数

哪怕做 5–10 人的小样本用户研究，对评委的说服力也远超功能自证。

#### 4.4 动机低谷的恢复机制

真实场景中动机必然波动。按**自我效能四来源**设计低谷期支持：

| 自我效能来源 | 系统动作 |
|---|---|
| 掌握经验 | 重设小目标、回顾已进步的证据 |
| 替代经验 | 同龄人匿名案例（"有同学也这样卡过"） |
| 言语说服 | 温和、具体的鼓励（非泛化鸡汤） |
| 生理/情绪唤醒 | 避免负面化表达；给休息/缩时的台阶 |

目前方案的重启手段只有"缩短 / 10 分钟起步任务 / 改期 / 静默"（§5.6），缺少系统化的"**怎么帮助学生重新开始**"设计（重设小目标、回顾进步证据、替代经验）。

### 🟡 中优先级（完善专业度）

#### 4.5 用理论命名现有设计

在方案书加一小节"教育理论依据"，把 SRL、SDT、ZPD、形成性评价、成长型思维与产品功能一一对应（即本文档第 1 节表格）。成本极低，收益很大。

#### 4.6 学科差异建模

知识图谱-错因模型适合数学，但语文/英语（阅读、写作、口语）不适合"知识节点"表达。

**建议**：学科包声明"建模范式"字段：

```json
{
  "id": "junior-math",
  "modeling_paradigm": "knowledge_graph",   // 数学：知识图谱
  "..." : "..."
}
```

语文/英语可声明 `"modeling_paradigm": "skill_dimensions"`（技能维度 + 文本类型），避免评委一问"语文怎么办"就露怯。

#### 4.7 AI 错误率与纠错机制

数学解题 LLM 会犯错。需求文档 §12.2 已有"重要结论提供来源或不确定性提示"、§5.5.4 已有学生更正机制（`student_correction` 优先），可在此基础补三点：

- 学生/家长可**举报错误解答**（目前只有学习状态的更正，没有解题内容的举报）
- 对**解题步骤**显示**置信度标注**（§12.2 的不确定性提示目前偏内容来源层面）
- 保留**人类教师纠错入口**

这既是教育伦理，也是现实必然。

### 🟢 低优先级（锦上添花）

#### 4.8 家校协同的正面叙事

家长端目前只有"周报 + 风险提示"（防御性设计）。可补一个积极场景：

> "周末家长与孩子一起看成长回顾、共同定下周一个目标"

把家长从"监控者"变成"支持者"（Bronfenbrenner 生态系统理论），也缓解"家长觉得被排除在外"的疑虑。

#### 4.9 数字孪生的可视化生长

评委看的是界面。方案书 §10 实现现状已确认"学习证据时间戳 + 周热力图 ✅ 已实现（activityLog / weeklyActivityFromLog）"，需求文档 §5.2 也有 growth_timeline。建议演示中进一步突出**证据溯源**（每条状态下面能看到是哪次反馈、哪张照片支撑的），让"生长的孪生"肉眼可见，而非停留在聚合面板。

#### 4.10 目标设定教学

需求文档 §7.1 已有目标确认对话（"我理解为'半年内提升数学成绩 20 分'，这个目标对你最重要的原因是什么？"），可再进一步**教学生把目标改写成可验证形式**（"怎么知道做到了"，如"4 周内函数图像转换错因率下降"）。这本身就是一次微型的 SRL 教学示范，评委印象深刻。

---

## 5. 一句话总结

> 方案**真实**，骨架已经站在正确的教育理念上（SRL + SDT + 脚手架 + 形成性评价），当前最大短板不是"不够智能"，而是**"放手"机制缺失、策略库单薄、效果评测缺席**。
>
> 补上这三块，它就从"设计得体的教育产品"升级为"有教育学立场的 AI 教育方案"。

> 修订注：以上"短板"指**量化与显式化程度**——需求文档已有放手表（§7.7）、干预策略表（§10）与自主能力成长指标（§2.3），但都停留在定性层面，未进入 Demo 与评测闭环。
