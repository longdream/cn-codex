## 1. 参赛叙事与价值主张

### 1.1 赛道要的不是“会聊天的题库”

GOAI AI+教育明确鼓励：个性化学习、作业辅导、学情诊断、多轮交互、任务闭环、教学友好与合规。  
不鼓励：泛聊天、答案机、无流程概念演示。

### 1.2 我们要做的：自学利器

真正好的自学体验：

> **点开任务，AI 主动开始；**  
> **需要你选择或填写时，弹出清晰的交互窗口，等你完成；**  
> **不是在聊天框里猜格式、输 A/B/C；**  
> **做完一步，系统才往下走。**

### 1.3 差异化对照

| 常见 AI 教育产品 | 本项目 |
|------------------|--------|
| 学生先想怎么问 | **点开任务，AI 主动开场** |
| 聊天框里手打选项/答案 | **选择题/填空/分析一律交互弹窗** |
| 抽象套题 | **真实场景任务，学了能用** |
| 随机刷题 | **多知识点 + 主链路任务** |
| 只判对错 | **分析任务 → 显式调用知识点 → 解决** |
| 学情靠感觉 | **全量交互事件驱动下一任务** |
| 左侧普通聊天 | **左侧每个会话 = 一个学习任务** |

### 1.4 评委 10 秒记住

```text
点开即学，AI 先引导。
要选要填，弹窗等待。
真实场景，知识点可见。
语音也能答，自学有教练。
交互全记录，任务自适应。
```

闭环：

```text
设置生成真实场景任务
 → 左侧点开任务
 → AI 主动引导
 → 需选择/输入时弹出 Interactive Modal，阻塞等待
 → 学生完成弹窗（点选/填写/语音转写确认）
 → 主链路推进：分析 → 调用知识点 → 解决 → 决策
 → 学情更新 → 动态下一任务 → 最终目标
```

## 2. 产品定义：自学利器 = 任务中心 + AI 主动引导

### 2.1 学习任务 Learning Task

任务不是单题，而是真实场景学习目标包：

```text
LearningTask
├── 真实场景 Scenario
├── 多知识点绑定 KnowledgeBinding[]
├── 主链路 MainChain
├── 主动开场 ProactiveOpening
├── 交互请求 InteractionRequest[]（弹窗题/输入）
├── 引导策略 + 语音策略
├── 成功标准
└── 学情回写规则
```

### 2.2 交互第一性原则（本次强化）

> **所有需要用户做选择、做填写、做确认的动作，不得只依赖自由文本聊天框“自己组织答案格式”；必须使用交互式弹窗（Interactive Modal / Dialog），并等待用户提交后，主流程才继续。**

这与 CN-Codex 已有 `ApprovalModal` / `request_user_input` 的产品直觉一致：  
**系统提问 → 弹层收集结构化输入 → 用户确认 → 再往下执行。**

### 2.3 任务必须真实可迁移

例：奶茶第二杯半价、预算够不够；满减 vs 折扣；分披萨是否公平。  
抽象“小明有苹果”不是首选。

### 2.4 教-学一体

| AI | 学生 | 平台 |
|----|------|------|
| 主动问、拆任务、点知识点、弹窗出题 | 在弹窗中选/填/说 | 阻塞等待、记事件、更新学情、推下一任务 |

## 3. 用户与场景

### 3.1 用户

- 自学学生：不知从何开始 → 点开即被引导；选项弹窗降低负担  
- 家长：可回看任务链路与薄弱点  
- 教师：设置中生成任务包  

### 3.2 Demo 主线

1. 任务工坊生成「奶茶半价」任务  
2. 左侧点开 → AI 主动开场  
3. **弹出**「想语音还是打字？」等待选择  
4. **弹出**先验问题，等待回答  
5. 发布真实场景；**弹出**任务分析表单  
6. 主链路每步 **弹窗检测**（选择/填空/点选知识点）  
7. 完成后学情更新 + 推荐下一任务

## 4. 信息架构与界面改造

### 4.1 布局

```text
┌─────────────┬──────────────────────────────┬──────────────┐
│ 左侧任务列表 │ 中间任务对话（引导/过程/反馈）│ 右侧情境     │
│ 点开即主动学 │ + 上层 Interactive Modal     │ 链路/知识点  │
└─────────────┴──────────────────────────────┴──────────────┘
```

**分层原则：**

| 层 | 放什么 |
|----|--------|
| 对话流 | AI 讲解、鼓励、小结、工具过程、已完成结果回显 |
| **交互弹窗** | **所有待选择、待输入、待确认的当前步骤** |
| 右侧 | 上下文（场景、进度、本步知识点），不承担强制输入 |

### 4.2 左侧：任务会话

- 一项 = 一个学习任务  
- 点开 → Proactive Session  
- 展示：场景名、主链路进度、状态、是否语音  

### 4.3 中间对话：只承载“过程与结果”，不承载“难填的表单”

对话区出现：

- 开场说明、场景故事、主链路地图（只读进度）  
- 工具过程（生成中/诊断中）  
- **“请在弹窗中完成本步”** 的占位提示  
- 学生提交后的答案回显与反馈  
- 任务完成卡、下一任务建议  

**不出现：** 让学生在聊天框里手打 `选C`、`答案是20`、`知识点：单位1` 这种脆弱交互（可作辅助，但不是主路径）。

### 4.4 设置

```text
设置 → 教学引擎
  ├── 任务工坊
  ├── 学生档案
  ├── 语音设置
  ├── 交互偏好（自动弹窗 / 动画 / 字体）
  └── 合规
```

## 5. 交互式弹窗协议（选择与输入的统一方式）

> 本章是体验核心。没有它，产品仍像“会出题的聊天框”。

### 5.1 硬规则

1. **需要用户选择**（单选/多选/是否/模态选择）→ 必须弹窗  
2. **需要用户输入内容**（填空、简答、列式、预算数字、分析表单项）→ 必须弹窗  
3. **需要用户确认**（开始任务、查看完整思路、生成下一任务）→ 弹窗或明确确认条  
4. 弹窗打开后，教学主链路进入 **`awaiting_user_input` 阻塞态**  
5. 仅当用户点击 **提交/确认**（或明确跳过且策略允许）后，才推进下一步  
6. 关闭弹窗若未提交：视为取消/稍后，不写错误学情；可再次打开  
7. 同一时刻默认只 prioritise **一个主交互弹窗**（可排队）  
8. 提交结果写入对话流回显 + `InteractionEvent`  

### 5.2 为什么必须弹窗，而不是纯聊天

| 纯聊天输入 | 交互弹窗 |
|------------|----------|
| 格式混乱（A/a/选项C） | 结构化选项，零歧义 |
| 不知道要填几项 | 表单字段清晰 |
| 语音转写后还要手改格式 | 转写填入字段，点提交即可 |
| 难做校验 | 必填、范围、题型校验内置 |
| 难无障碍 | 焦点管理、键盘操作、读屏友好 |
| 过程像“对答案” | 过程像“课堂互动题板” |

### 5.3 弹窗类型（Education Modal Kit）

| 类型 | 用途 | 示例 |
|------|------|------|
| `choice` | 单选 | 单位1是谁？A/B/C/D |
| `multi_choice` | 多选 | 本步可能用到哪些知识点 |
| `confirm` | 是/否或双按钮 | 是否开始任务 / 是否查看完整思路 |
| `text_input` | 单行填空 | 实付多少元？ |
| `textarea` | 简答/解释 | 说说为什么是单位1 |
| `form` | 多字段 | 任务分析：已知/所求/关键句 |
| `number` | 数值 | 预算、数量 |
| `expression` | 列式 | `16+16*1/2` |
| `knowledge_pick` | 知识点点选 | 本步我用到了… |
| `voice_compose` | 语音作答面板 | 录音→转写→编辑→提交 |
| `mixed` | 选择+解释 | 选项 + “理由”必填 |

所有类型共享同一套壳：标题、题目/说明、主体控件、次要操作、主提交、可选提示。

### 5.4 弹窗信息架构（视觉对齐现有产品）

参考 `ApprovalModal` / 设置结果对话框的层级：

```text
┌─────────────────────────────────────────────┐
│ 步骤徽章 · 主链路 3/7 · 找单位1              │
│ 题目/问题（可 TTS 播报）                     │
│ 本步知识点提示（可折叠）                     │
├─────────────────────────────────────────────┤
│ 交互区：选项 / 输入框 / 表单 / 语音转写      │
│ 校验提示：请选择一项才能继续                 │
├─────────────────────────────────────────────┤
│ [要提示] [跳过/稍后]     [提交/继续]         │
└─────────────────────────────────────────────┘
遮罩锁定背景对话；提交前主流程不推进
```

样式原则：

- 遮罩 + 居中卡片，圆角与 `chat-work-card` 一致  
- 主按钮用 accent；危险/放弃用次要样式  
- 移动端可改为底部 sheet，但逻辑仍是“阻塞等待”  
- 打开时自动聚焦第一个控件；Esc = 取消（若允许）  

### 5.5 触发时机（什么时候弹）

| 时机 | 弹窗 |
|------|------|
| 点开任务后的模态选择 | 语音 or 文字 |
| 主动开场的先验探测 | 选择/简答弹窗 |
| 场景任务发布后 | 「开始分析」确认 |
| 任务分析步 | form 弹窗 |
| 每个 checkpoint | choice / input / mixed |
| 点选本步知识点 | knowledge_pick |
| 要提示 | 可选 confirm 显示下一级提示 |
| 任务完成迁移 | textarea / voice_compose |
| 生成下一任务 | confirm |

对话里可以有按钮「打开本题」；**默认在轮到学生时自动弹出**，减少漏操作。

### 5.6 阻塞等待状态机

```text
AI 完成讲解/出题准备
  → open EducationModal(request)
  → state = awaiting_user_input
  → 禁用“误推进”的主链路自动跳步
  → 用户编辑中（text/voice partial）
  → submit
  → validate
  → close modal
  → append message echo + event
  → grade / update learner
  → next step or remediate
```

关键：

- `awaiting_user_input` 时 Agent **不得**假装学生已答继续讲下一步  
- 可并行展示只读信息（链路地图、知识点说明），但不可用另一弹窗抢焦点  
- 超时：轻提示“还在这题哦”，不自动提交错误答案  

### 5.7 InteractionRequest 数据模型

```json
{
  "request_id": "req_step3_unit1",
  "task_id": "task.milk_tea_half_price",
  "thread_id": "thr_...",
  "chain_step_key": "find_unit1",
  "blocking": true,
  "ui": {
    "mode": "modal",
    "size": "md",
    "auto_open": true,
    "allow_dismiss": true,
    "tts_question": true
  },
  "content": {
    "title": "找出单位1",
    "prompt": "第二杯半价时，这里的“1/2”是相对于谁？",
    "help": "单位1通常是被当作“全部/原价参照”的量",
    "knowledge_hint": ["小学_数学_单位1", "小学_数学_分数意义"]
  },
  "fields": [
    {
      "id": "choice",
      "type": "choice",
      "required": true,
      "options": [
        {"value": "A", "label": "半价后的第二杯价格"},
        {"value": "B", "label": "一杯奶茶原价", "correct": true},
        {"value": "C", "label": "两杯实付总价"},
        {"value": "D", "label": "预算30元"}
      ]
    },
    {
      "id": "reason",
      "type": "textarea",
      "required": false,
      "placeholder": "用一句话说说为什么（可语音转写）"
    }
  ],
  "actions": [
    {"id": "hint", "role": "secondary"},
    {"id": "submit", "role": "primary"}
  ],
  "response_schema": {
    "choice": "string",
    "reason": "string?"
  }
}
```

### 5.8 提交后的对话回显

弹窗关闭后，在对话流插入结构化回显（只读卡片）：

```text
你的回答 · 找单位1
选择：B 一杯奶茶原价
理由：半价是原价的一半
[再改一次]
```

然后 AI 反馈卡：对/错因/下一步。  
**回显可再打开弹窗修改（策略允许时）**，修改会追加事件而非静默覆盖。

### 5.9 与底部输入框的关系

| 输入框 | 弹窗 |
|--------|------|
| 自由追问：“我不懂半价” | 结构化作答、选题、填表 |
| 快捷意图：“给我提示” | 当前 checkpoint 的正式提交 |
| 语音闲聊式求助 | 语音填入弹窗字段 |

原则：

- **正式学习证据以弹窗提交为准**  
- 聊天框补充解释可并入下一次诊断上下文  
- 若用户在聊天框直接打了答案，Agent 可 **引导打开对应弹窗并预填**，而不是静默算作提交（避免误触）  

### 5.10 语音如何进入弹窗

```text
弹窗打开
 → 用户点麦 / 自动听写（设置项）
 → ASR partial 显示在当前焦点字段
 → 用户改字
 → 提交（与手输同一路径）
```

禁止：语音识别完自动提交且无法修改。

### 5.11 无障碍与体验细节

- 焦点陷阱在弹窗内  
- 选项支持键盘上下/数字键  
- 主按钮在校验通过前禁用或点击给红字提示  
- 低龄模式：更大热区、更少同屏字段  
- 动画克制，不挡住读题  

### 5.12 反模式

1. 只说“请回复 A/B/C”却不弹窗  
2. 多题塞进一个超长弹窗一次答完（应一步一窗或向导分页）  
3. 弹窗可被背景操作绕过导致状态错乱  
4. 关闭即判错  
5. 无回显，用户不知道系统记了什么  
6. 用原生 `window.prompt` 这种简陋框（必须产品化 Education Modal）

## 6. 核心对象模型

### 6.1 全景

```text
Goal
 └── LearningTask
       ├── Scenario
       ├── KnowledgeBinding[]
       ├── MainChain
       ├── ProactiveOpening
       ├── InteractionRequest templates（弹窗题模）
       └── TaskThread
             ├── ModalQueue（当前阻塞请求）
             └── InteractionEvent[]
```

### 6.2 LearningTask（摘要字段）

```json
{
  "id": "task.milk_tea_half_price",
  "title": "周末点奶茶：第二杯半价省多少？",
  "scenario": {"domain": "life.shopping", "setting": "...", "why_it_matters": "..."},
  "knowledge_bindings": [{"node_id": "小学_数学_单位1", "role": "core"}],
  "main_chain_id": "chain.life_problem.standard",
  "interaction_policy": {
    "input_mode": "modal_first",
    "auto_open_modal": true,
    "chat_freeform_is_auxiliary": true,
    "require_submit_to_advance": true
  },
  "modality": {"text": true, "voice_in": true, "voice_out": true}
}
```

### 6.3 MainChain（含分析与知识点）

`warm_in → analyze → knowledge_preview → find_unit1 → mapping → model → solve → check → transfer`  
每步挂载一个或多个 `InteractionRequest` 模板。

### 6.4 事件（弹窗生命周期）

```text
modal_open → modal_field_change → voice_fill
 → modal_submit → modal_validate_fail?
 → modal_close → grade → learner_update
```

```json
{
  "type": "modal_submit",
  "request_id": "req_step3_unit1",
  "modality": "voice",
  "payload": {"choice": "B", "reason": "半价相对原价"},
  "derived": {"correctness": "correct", "knowledge_signals": []}
}
```

## 7. 主链路生成：设置里如何创建真实场景任务

### 7.1 任务工坊

选知识点 → 选主链路 → 配真实场景 → 配主动开场 → **为每步生成弹窗交互题** → 预览 → 创建左侧任务。

### 7.2 生成时必须产出弹窗，而不是“聊天问答题面”

校验器增加：

- [ ] 每个 must_pass 步骤有 `InteractionRequest`  
- [ ] 选择/输入字段 schema 完整  
- [ ] `blocking=true` 与 `auto_open` 策略明确  
- [ ] 场景真实可迁移  
- [ ] 知识点绑定到步骤  

### 7.3 预览

除场景与链路外，预览 **第 N 步弹窗长什么样**（可试点）。

---

## 8. 点开即学：AI 主动会话协议

### 8.1 触发

`loadTaskThread` / 左侧选中 → `edu_start_proactive_session` → 第一句引导 → **立刻打开第一个交互弹窗**（如模态选择/热身题）。

### 8.2 五段式 + 弹窗

| 阶段 | AI | 弹窗 |
|------|----|------|
| 打招呼 | 说明任务 | — |
| 模态选择 | 问语音还是文字 | `choice` 弹窗等待 |
| 先验探测 | 问以前怎么算 | `choice`/`textarea`/`voice_compose` |
| 场景钩子 | 讲奶茶故事 | `confirm` 开始分析 |
| 进入主链 | 说明下一步 | 自动打开分析 form |

### 8.3 原则

- 主动，但 **每轮一个主弹窗问题**  
- 不连发多个阻塞窗  
- 学生可点“跳过热身”，仍进入场景分析弹窗  

---

## 9. 任务内教学闭环：分析任务 → 调用知识点 → 解决

### 9.1 流程

```text
主动引导
 → 弹窗热身
 → 场景发布（对话卡）
 → 弹窗：任务分析 form
 → 弹窗：预判知识点 multi_choice
 → 逐步：
      对话简短引导
      → 弹窗 checkpoint（选择/输入）
      → 回显 + 反馈
      → 记录知识点调用
 → 弹窗：生活决策
 → 弹窗：迁移反思
 → 完成卡 + 下一任务 confirm 弹窗
```

### 9.2 任务分析弹窗（示例）

```text
标题：先分析，再计算
字段：
- 已知（textarea）
- 所求（textarea）
- 关键规则句（text）
- 我可能用到的知识点（multi_choice）
主按钮：提交分析
次按钮：要提示
```

### 9.3 知识点显式化

- 步骤只读条：本步应调用的知识  
- 弹窗内 `knowledge_pick`：学生点选“我用到了…”  
- 成功标准可要求 `must_name_knowledge=true`  

### 9.4 反馈仍在对话流

弹窗负责 **采集**；对话负责 **教与反馈叙事**。两者分工清晰。

## 10. 多模态输入：语音 + 文字

### 10.1 语音主路径 = 弹窗内语音

不是另起一套语音聊天替代弹窗，而是：

**弹窗字段支持语音填充。**

### 10.2 MVP

- 语音输入 + 转写编辑 + 提交  
- 开场 TTS 可选  
- 失败降级纯文本弹窗  

### 10.3 输入框

保留自由提问；正式作答以弹窗为准。

## 11. 全量交互记录与学情引擎

记录弹窗打开、修改、提交、提示、跳过；  
评分基于 `modal_submit` 结构化字段；  
根因回退仍按主链路。

额外习惯信号：

- 是否常跳过弹窗  
- 语音填写占比  
- 提交前修改次数（犹豫度）

## 12. 动态任务编排：到达最终目标

依据 Goal 缺口、场景迁移覆盖、弹窗作答证据、卡点步骤生成下一任务；  
下一任务创建后出现在左侧，点开仍是 **主动引导 + 弹窗交互**。

## 14. Agent 能力与工具闭环

## 17. 评测、合规与差异化

### 17.1 体验指标

| 指标 | 目标 |
|------|------|
| 结构化作答弹窗率 | 正式 checkpoint 100% 走弹窗 |
| 阻塞正确率 | 未提交不推进步骤 = 100% |
| 误格式输入率 | 接近 0（对比纯聊天） |
| 点开到首个弹窗时间 | 尽量 < 2s（不含模型） |
| 语音填窗可编辑提交 | 支持 |

### 17.2 合规

辅助自学；本地数据；语音可关可删；不替代正式评价。

### 17.3 路演句

> 点开任务，AI 主动教；  
> 要你选、要你填，都弹窗等你完成；  
> 真实生活题 + 知识点主链路 + 学情自适应——自学真正好用。

## 18. 结论

### 18.1 产品形态

| 模块 | 职责 |
|------|------|
| 任务工坊 | 生成真实场景 + 主链路 + **弹窗交互题** |
| 左侧任务 | 点开即学 |
| 对话流 | 引导、反馈、回显、过程 |
| **Education Modal** | **所有选择与输入的主交互面，阻塞等待** |
| 学情引擎 | 用结构化提交驱动下一任务 |

### 18.2 相对 v3 的强化

| 点 | v4 |
|----|----|
| 作答方式 | **交互式弹窗优先，聊天框辅助** |
| 流程控制 | **未提交不推进** |
| 题型承载 | choice/form/voice_compose 统一 Modal Kit |
| 工程对齐 | 复用 Approval/user_input 等待范式 |

### 18.3 待确认

1. 正式作答是否 **强制只能弹窗提交**（推荐是）？  
2. 弹窗默认 **自动弹出** 还是对话内点「开始作答」？  
3. MVP 是否先做 `choice + text + form` 三种？  
4. 语音是否第一期就做进弹窗？  

确认后可直接产出：

- `InteractionRequest` JSON Schema  
- EducationModalHost 线框与状态表  
- 3 个带弹窗步骤的任务样例  
- 与 `ApprovalModal` 的复用/独立方案对比
