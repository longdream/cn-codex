## 1. 参赛叙事

### 1.1 要解决的真实问题

学生的学习困难通常不是“没有一道题的答案”，而是：

- 不知道如何把长期目标拆成可执行步骤；
- 知道要学习，却难以按时启动并持续执行；
- 纸质作业、教材阅读、试卷训练等线下学习没有被理解；
- 连续受挫时，只得到泛化鼓励或直接答案，而没有得到合适的学习策略；
- 一次性生成的静态计划，无法随着学生状态、节奏和信心变化而调整。

普通 AI 陪读通常在学生提问后回答，普通任务工具通常只记录“是否完成”。两者都无法形成长期、可解释、可调整的教育闭环。

### 1.2 本项目的回答

AI自主学习教练不是答题工具、陪读工具或打卡工具，而是模拟优秀教师长期教育行为的主动式 Agent 系统：

```text
理解学生
  → 共同建立目标
  → 生成可执行计划
  → 在恰当时机主动沟通
  → 捕获线上与线下学习证据
  → 诊断困难与状态变化
  → 调整任务、策略与支持强度
  → 帮助学生逐步接管自己的学习管理
```

系统不替代教师、不替代家长、不替代学校正式评价。它负责在授权边界内提供辅助性学习支持，并将学生的选择权、知情权和数据控制权置于首位。

### 1.3 评委 10 秒记忆点

```text
不是等学生提问，而是理解学生后主动陪伴。
不是静态档案，而是会随学习证据变化的数字孪生。
不是只看线上行为，而是连接真实的线下学习。
不是给答案，而是逐步把学习管理能力还给学生。
```

### 1.4 GOAI 赛道映射

| 评审维度 | 本系统的可见能力 |
|---|---|
| 场景价值 | 围绕长期目标、日常任务、线下作业与受挫干预的真实学习场景 |
| Agent 能力 | 规划、陪伴、成长分析、干预策略在主管 Agent 调度下协作闭环 |
| 个性化 | 学生数字孪生统一建模目标、知识、习惯、动机、自我效能与状态 |
| 交互体验 | AI 主动发起但不过度打扰；关键选择与反馈采用结构化交互 |
| 可演示性 | 可完整演示“建立画像→主动启动→线下反馈→状态更新→计划调整” |
| 合规性 | 最小化采集、可解释建议、风险分级、可删可导出、人工转介边界 |

## 2. 产品定义、目标与边界

### 2.1 产品定位

**AI自主学习教练系统**是一个长期学习支持系统。系统以学生数字孪生（Student Digital Twin）为动态成长模型，通过主动式教育 Agent 提供目标管理、学习规划、任务陪伴、学习反思和策略调整。

核心理念：

> 从“教师管理学生学习”，转变为“AI帮助学生形成自主学习能力”。

### 2.2 建设目标

1. **建立学生数字孪生**：动态反映知识掌握、行为习惯、目标进度、动机、自我效能、学习策略和非临床的学习状态。
2. **实现主动式教育交互**：基于计划、时间、学习证据和学生偏好，在合适时机发起可拒绝、可调整的学习沟通。
3. **形成线上线下一体化闭环**：将纸质作业、教材阅读、试卷训练等线下活动通过学生主动反馈和可选证据回流系统。
4. **培养自主调节学习能力**：帮助学生练习目标管理、时间管理、自我监控、反思和策略调整，而非让学生依赖 AI。

### 2.3 成功标准

| 目标 | 可衡量结果 |
|---|---|
| 目标清晰 | 完成初始化后，每位学生至少有一个长期目标、阶段目标和最近一周任务 |
| 计划可执行 | 每个任务具备预计时长、建议时间窗、完成证据和调整规则 |
| 主动干预有效 | 学生可在开始、稍后、改期、暂停中明确选择，系统不擅自推进 |
| 状态可追溯 | 每次计划调整可回溯到任务反馈、学习证据、学生自评或明确规则 |
| 自主能力成长 | 周期回顾中呈现目标复盘、计划调整和学习策略的学生自主决策证据 |
| 合规可控 | 学生或监护人可查看、更正、导出、删除授权范围内的数据 |

### 2.4 非目标

- 不提供心理疾病诊断、治疗建议或危机干预替代服务。
- 不代替学校正式评价、升学决策或教师专业判断。
- 不对学生进行自动化惩罚、排名或标签化。
- 不要求上传人脸、持续音视频或与学习无关的个人信息。
- 不用高频提醒和焦虑话术驱动学习。

## 3. 用户、角色与关键旅程

### 3.1 用户角色

| 角色 | 核心诉求 | 系统权限与边界 |
|---|---|---|
| 学生 | 理清目标、按计划开始、获得适合自己的支持、看到成长 | 查看和修正自己的画像；管理提醒；确认任务反馈 |
| 家长/监护人 | 了解学习支持是否有效，不过度侵入学生空间 | 在授权范围内查看周报和风险提示；不可默认查看私密对话全文 |
| 教师/辅导者 | 识别需要帮助的学生，获得可操作的教学线索 | 查看聚合学情和学生授权的任务记录；最终教育判断由人作出 |
| 管理员 | 配置内容、账户、数据策略和审计 | 仅处理必要系统管理数据，不能任意浏览学生内容 |

### 3.2 学生端完整旅程

```text
首次对话建档
  → 学生确认目标与可学习时间
  → 生成首周计划
  → 到达学习时间窗，AI 主动询问是否开始
  → 学生完成线上或线下任务
  → 通过结构化反馈说明完成情况、难点和信心
  → 数字孪生更新
  → Agent 判断继续、降阶、换策略或改期
  → 周期回顾中由学生复盘并共同调整下周计划
```

### 3.3 核心演示场景：从线下作业到动态调整

**角色**：初二学生小林；目标为“半年内数学提升 20 分”。

1. AI 通过自然对话识别目标、可学习时间、当前薄弱点与偏好；学生确认画像摘要。
2. 规划 Agent 生成“函数基础修复→重点专题强化→综合训练→模拟复盘”的阶段路线，并创建当天 30 分钟任务。
3. 晚 20:00，陪伴 Agent 主动发起结构化询问：`开始学习 / 稍后开始 / 调整时间 / 今天暂停`。
4. 小林选择“开始学习”，完成纸质二次函数练习。
5. AI 在任务结束后询问：`是否完成`、`哪类题最费时`、`难度感受`、`下次信心`；小林反馈“完成了，但图像与解析式转换总错”。
6. 成长分析 Agent 将反馈与既有错误证据关联，发现同一知识点连续受阻；系统不直接给出答案，而是建议下一次采用“图像—列表—表达式映射”的低难度任务。
7. 干预策略 Agent 调整明日任务难度、时长和教学策略；学生确认后写回计划。
8. 周末，AI 展示“函数基础题完成率上升、图像转换仍需练习”的成长回顾，邀请学生自己选择下周的首要改进项。

## 4. 总体架构

### 4.1 逻辑架构

```text
                         AI 学习教练
                               │
                   Supervisor Agent（主管）
                               │
      ┌────────────────┬───────┼───────────────┬────────────────┐
      │                │       │               │                │
  规划 Agent       陪伴 Agent  成长分析 Agent    干预策略 Agent   安全与合规策略
      │                │       │               │                │
      └────────────────┴───────┼───────────────┴────────────────┘
                               │
                       学生数字孪生
                               │
      ┌────────────────┬───────┼───────────────┬────────────────┐
      │                │       │               │                │
  知识与策略       执行行为     目标与计划       反思调节/动机与学习情感
                               │
                  任务执行与证据层
         线上学习 · 结构化交互 · 线下学习反馈 · 可选语音
```

### 4.2 分层职责

| 层级 | 职责 | 关键约束 |
|---|---|---|
| 交互层 | 任务列表、对话、反馈表单、回顾视图、提醒设置 | 学生明确确认；重要输入结构化；不通过自由聊天猜测关键状态 |
| 编排层 | 调度 Agent、执行规则、控制主动消息频率、维护任务状态机 | 高影响变更需学生确认；所有调整可追溯 |
| 孪生层 | 维护并解释学生成长模型 | 区分事实、学生自评、模型推断；推断有置信度与有效期 |
| 数据层 | 计划、任务、交互事件、授权、审计记录 | 最小化采集、用途限定、可导出/删除、权限隔离 |
| 安全层 | 内容安全、风险识别、未成年人保护、人工升级 | 不做医疗诊断；高风险场景停止自动干预并提示专业支持 |

### 4.3 执行分层：让功能在中国 Codex 教育版上“感觉顺畅”

CN-Codex 的完整 Agent 轮次（模型推理、工具搜索、多轮 tool call、会话写盘）天然偏慢，不适合作为每一次学习事件的同步主路径。教育系统必须把“学生马上要感知的动作”和“可以稍后完成的深度思考”拆开：

```text
学生动作 / 时钟触发
  → L0 规则引擎（本地、毫秒级）：写入事件、更新任务状态机、打开弹窗、回显确认
  → L1 模板与轻量策略（本地或短调用、通常 < 1–2s）：选择话术模板、组装选项、计算简单规则洞察
  → L2 深度 Agent 编排（异步、可排队、可取消）：成长分析、计划重排、长解释生成
  → UI 始终可交互：先给即时反馈，再逐步替换为更完整结果
```

| 路径 | 典型时延目标 | 谁执行 | 允许做什么 | 禁止做什么 |
|---|---|---|---|---|
| L0 即时路径 | < 200ms（本机） | 教育状态机 + 本地规则 | 记录事件、切换任务状态、打开/关闭 Modal、频控判定、授权检查 | 不调用完整 Supervisor 多 Agent 链；不阻塞 UI |
| L1 轻量路径 | 通常 < 2s | 模板引擎 / 小模型或规则 | 选择温度化话术模板、生成 3–4 个选项、简单错因规则命中 | 不重写长期目标；不做长篇分析 |
| L2 深度路径 | 数秒至数十秒，异步 | CN-Codex Agent 轮次 | 周计划生成、复杂诊断、可解释长文、跨任务证据关联 | 不阻塞学生当前输入；不自动强制改计划 |

**顺畅性硬规则**：

1. **学生点击后必须先有即时反馈**：至少更新按钮状态、任务状态或弹窗，不等待 L2 完成。
2. **一次用户动作最多触发一次 L2 编排**；连续点击合并为同一 `orchestration_job`。
3. **默认不串行跑齐 5 个 Agent**；Supervisor 先做路由，只调度必要子能力，且优先 L0/L1。
4. **主动提醒不依赖实时长推理**：到点消息优先用预渲染模板 + 最新孪生摘要缓存；深度个性化在后台刷新。
5. **弹窗等待态与 Agent 慢路径解耦**：`awaiting_user_input` 只等人，不等人模型；模型慢时显示“正在整理建议…”，学生仍可改期/暂停/跳过。
6. **温度优先用模板落地**：温暖接纳、共情、控制权确认等固定骨架来自话术库；模型只填充必要个性化片段，避免“为了有温度而多跑一轮慢 Agent”。

## 5. 学生数字孪生（Student Digital Twin）

### 5.1 定义、目的与边界

学生数字孪生不是静态学生档案、成绩预测器或“给学生贴标签”的系统。它是由学习事实、学生主动自评、经授权的教育证据和有限规则推断组成的**可解释成长模型**，用于回答三个教育问题：

1. 学生当前为了目标，正在学什么、怎样学、卡在哪里？
2. 相比自己的历史基线，学生的学习状态是在改善、波动还是需要支持？
3. 下一步应提供什么脚手架，并在什么时候把选择权还给学生？

模型原则：

- **面向自主调节学习**：建模目的为支持学生的目标、计划、执行、监控、反思与调整能力，不是替学生作决定。
- **可见、可解释、可修正**：学生能查看每项关键状态的近期证据、时间范围和建议，可更正或关闭相关建议。
- **事实、自评、推断分层**：完成记录是事实；“我很疲劳”是学生自评；“这周可能需要减少任务粒度”只能是待确认的系统建议。
- **时间敏感而非永久标签**：动态状态以时间序列呈现，显示趋势、覆盖度与有效期；不得将短期波动写入长期人格结论。
- **上下文隔离**：数学中的信心或困难不能直接迁移为语文、家庭或整体人格的判断。
- **最小化与目的限定**：只处理完成学习支持所需的数据；无摄像头、无面部表情识别、无眼动、无声纹、无键盘节律或其他生物特征推断。

### 5.2 孪生的双层结构

```text
StudentTwin
├── 相对稳定层 Profile
│   ├── identity_profile            基础资料、年龄段、授权状态
│   ├── goal_model                  长期 / 阶段 / 短期目标与优先级
│   ├── knowledge_model             知识点、错因、掌握证据
│   ├── interest_preference_model   兴趣主题、内容和交互偏好
│   └── support_preferences         提醒时间、语音/文本、共享与隐私偏好
├── 五维动态学习状态 LearningStateSeries
│   ├── goal_planning               目标与计划管理
│   ├── engagement_execution        学习投入与执行调节
│   ├── cognition_strategy          认知理解与学习策略使用
│   ├── monitoring_reflection       自我监控、归因与反思调节
│   └── motivation_affect           动机、自我效能与学习情感
├── evidence_ledger                 带来源、时间和授权的原子证据
├── intervention_history            建议、学生选择、实际效果
├── long_term_memory                经学生确认且与学习有关的长期记忆
└── growth_timeline                 目标、计划、任务、状态和回顾的时间轴
```

稳定层用于个性化与授权管理；五维动态层用于判断“此刻如何支持”。两者物理和逻辑上分别存储，动态状态不可反向覆盖学生已确认的稳定偏好。

### 5.3 五个核心维度：面向自主学习能力培养的学习状态模型

五维状态是学习过程的观察框架，不是对学生优劣的总分。每个维度均按**学科 / 目标 / 时间窗**存储，禁止用一个全局分数概括学生。

| 维度 | 教育含义 | 可观察证据 | 系统可做的支持 | 禁止推断 |
|---|---|---|---|---|
| 1. 目标与计划管理 `goal_planning` | 能否把愿望转为目标，并安排现实的下一步 | 目标是否经学生确认、计划是否由学生调整、时间窗是否匹配、复盘中是否能说出下一步 | 把长期目标拆为一周任务；提供缓冲；邀请学生重排而非自动塞满日程 | 不把计划未完成判定为自律差 |
| 2. 学习投入与执行调节 `engagement_execution` | 能否启动、持续、暂停和恢复学习 | 任务开始/完成/改期、实际用时、主动暂停、学生填写的未完成原因 | 提供 10 分钟起步任务、改时间、减少负荷、关闭提醒 | 不从在线时长、点击数或沉默推断努力程度或情绪 |
| 3. 认知理解与学习策略 `cognition_strategy` | 对知识的理解、错误模式及策略使用情况 | 结构化作答、错因、学生解释、所选策略、线下反馈 | 回退先备知识、换表征、示范策略、缩小题组 | 不用一次错题认定“不会”或“能力低” |
| 4. 自我监控与反思调节 `monitoring_reflection` | 能否估计难度、检查过程、解释成败并调整方法 | 难度预测与实际对比、提交前检查、反思文本、是否主动调整计划 | 提供“证据—原因—下一步”模板，逐步减少提示 | 不把不愿填写长反思视为缺乏反思能力 |
| 5. 动机、自我效能与学习情感 `motivation_affect` | 对目标价值、完成信心、当下精力和学习感受的自我觉察 | 主动量表、自愿文字/语音表述、任务价值和信心自评 | 调整任务粒度、支持语气、休息建议、允许改期或暂停 | 不诊断心理健康；不从摄像头、语音音色、面部或行为隐式识别情绪 |

五维的“成长”表现为学生越来越能自行设定目标、安排时间、使用策略、监控效果、表达需要并调整计划，而不是各项分值持续升高。

### 5.4 情绪与学习情感模型：主动反馈，不做摄像头采集

本系统不用摄像头、面部表情、眼动、姿态、声纹、语速音调、键盘节律或后台停留时长识别学生情绪。语音功能仅在学生启用并提交后转写为文本；系统不分析副语言特征，也不保留原始音频超过完成转写所必需的时段。

系统建模的是**与当前学习任务相关的主观学习感受**，而不是“识别真实情绪”。默认在以下低打扰节点提供可跳过的自评：任务开始、任务结束、学生主动要求调整、每周回顾。每次最多询问一个主题，避免情绪问卷化。

| 子变量 | 推荐交互 | 记录方式 | 有效期与用途 |
|---|---|---|---|
| 精力/疲劳 | “现在的精力如何？”：充足 / 一般 / 有点累 / 想休息 | `energy_level`，学生自评 | 默认至当日结束；仅影响任务粒度和提醒语气 |
| 任务感受 | “做这项任务时，你更接近哪种感受？”：平稳 / 有兴趣 / 有点挫败 / 有压力 | `task_affect`，与任务绑定 | 默认 24 小时；用于选择支持语气或建议暂停 |
| 完成信心 | “下次遇到类似任务，你觉得自己能完成吗？”：1–5 | `self_efficacy`，与知识点/任务绑定 | 以 14 天窗口呈现趋势；用于提示强度与难度梯度 |
| 目标价值 | “这周的这个目标对你重要吗？”：1–5，可跳过 | `task_value`，与目标绑定 | 周回顾使用；用于重新讨论目标，不用于施压 |

**文字/语音中的情感表述处理**：学生主动说“我今天很累”或“我被这类题弄得很烦”时，系统只将其视为当次对话上下文；若需要写入孪生，必须以可见确认询问：“要把‘今天有点累’作为今天的学习状态，用来把任务改轻一点吗？”学生同意后才形成 `student_self_report` 事件。没有确认时，不进入长期画像。

**行为信号的严格边界**：连续改期、未开始、耗时变长、错误增多只能产生“计划与支持方式可能不匹配”的假设，触发一次中性询问，例如“这个时间安排还合适吗？”。它们不得自动被解释为焦虑、厌学、抑郁、懒惰或缺乏意志力。

### 5.5 时间序列：从一次事件到可解释趋势

每个动态维度由不可变的 `StateObservation` 事件组成；系统展示的是事件在特定窗口内的汇总视图，而不是覆盖原始事实的单一分数。

```text
原始事件（某时刻、某任务、某学科）
  → 来源和授权校验
  → 写入 StateObservation
  → 按维度/学科/目标进入时间序列
  → 计算最近窗口的水平、趋势、波动、证据覆盖度
  → 生成“可询问或可选建议”，不直接生成高影响结论
```

#### 5.5.1 原子观测记录

```json
{
  "observation_id": "obs_20260727_001",
  "student_id": "stu_001",
  "dimension": "motivation_affect",
  "subdimension": "energy_level",
  "scope": {"subject": "math", "goal_id": "goal_math", "task_id": "task_function_basics_001"},
  "value": "a_little_tired",
  "source_type": "student_self_report",
  "captured_at": "2026-07-27T20:32:00+08:00",
  "confidence": "high",
  "expires_at": "2026-07-27T23:59:59+08:00",
  "consent_ref": "consent_learning_state_v1",
  "student_visible": true,
  "student_editable": true
}
```

`source_type` 只能取以下值：`student_self_report`、`student_confirmed_text`、`task_fact`、`structured_answer`、`teacher_authorized_record`、`system_inference_pending_confirmation`。其中最后一类不得直接更新稳定画像，也不得作为负面评价依据。

#### 5.5.2 窗口、衰减与趋势规则

| 状态类型 | 计算窗口 | 衰减规则 | 形成趋势的最低条件 | 页面呈现 |
|---|---|---|---|---|
| 任务级状态 | 单次任务至 24 小时 | 到期后不参与当前状态判断，原始事件仍可审计 | 不计算跨任务趋势 | “本次任务反馈” |
| 日级执行/精力 | 最近 7 天 | 越近事件权重越高；未填写不补零 | 至少 3 个不同日期的有效观测 | 稳定 / 上升 / 下降 / 波动 / 证据不足 |
| 周级计划、反思、价值 | 最近 4 周 | 使用周聚合，近两周权重更高 | 至少 3 个周度观测 | 趋势箭头 + 依据数量 |
| 知识与策略 | 最近 14 天同知识点证据 | 以最新且同类任务证据为主 | 至少 3 条相关证据，且至少来自 2 次任务 | “需巩固 / 有进展 / 证据不足” |

实现采用可解释的加权移动平均，而不是黑箱分类器。对于数值型自评：

```text
state(t) = Σ(w_i × value_i) / Σ(w_i)
w_i = source_weight × exp(-days_since_observation / half_life)
```

- `source_weight`：学生自评和学生确认文本为 1.0；结构化任务事实为 0.8；教师授权记录为 0.8；待确认的系统推断不进入正式计算。
- `half_life`：日级状态为 3 天，周级状态为 14 天；任务级感受按有效期自动失效。
- **缺失不是 0 分**：未反馈、未登录、未完成任务均不补为负分；页面显示“证据不足”。
- **趋势不等于因果**：系统只能说“最近 7 天的自评精力较前一窗口更低”，不能声称“因为某课程导致疲劳”。

#### 5.5.3 个体基线与异常识别

系统先建立学生自己的历史基线，不与同龄人、班级或排行榜比较。只有满足“至少 3 个有效窗口、最近窗口覆盖度不低于 60%”时，才显示趋势。异常规则只用来发起温和询问：

- 计划执行率连续两个周窗口低于学生自身 4 周中位水平 20 个百分点；
- 同一知识点在至少两次任务中重复出现同类错因；
- 学生在同一知识点的完成信心连续两个有效窗口下降至少 1 个量表档位；
- 学生主动连续两次报告“想休息”或“有压力”。

命中规则后，系统输出“可能需要调整”的提示和可选方案，不自动修改长期目标，不自动通知监护人，也不对学生作任何负向评价。

#### 5.5.4 状态合并、纠错与失效规则

为避免“模型猜测覆盖学生表达”，每一条状态在计算和展示时必须携带来源优先级。优先级只决定同一时间窗内相同字段的呈现，不删除原始证据。

| 优先级 | 来源 | 可写入范围 | 覆盖规则 |
|---|---|---|---|
| 1 | 学生主动更正 `student_correction` | 与更正范围相同的动态快照和可编辑稳定字段 | 立即使旧快照失效；后续建议使用更正值，原值保留审计痕迹 |
| 2 | 学生结构化自评 `student_self_report` | 自我效能、精力、任务感受、目标价值等主观变量 | 对同一任务/同一有效期内的系统待确认推断有最高优先级 |
| 3 | 学生确认的文本/语音转写 `student_confirmed_text` | 明确同意记录的学习感受、困难和策略 | 写入时必须记录确认界面、字段、有效期和原文摘要 |
| 4 | 结构化任务事实与作答 `task_fact` / `structured_answer` | 完成状态、用时、知识与策略证据 | 只影响执行、认知与反思维度；不得映射为情感事实 |
| 5 | 教师授权记录 `teacher_authorized_record` | 经授权的教学观察与作业证据 | 不得覆盖学生对主观感受的自评；与学生冲突时标记“待共同澄清” |
| 6 | 系统待确认推断 `system_inference_pending_confirmation` | 仅可生成询问和建议候选 | 永不作为正式状态、评分、排名、通知或跨会话记忆输入 |

具体规则：

1. 学生点击“这不准确”后，系统先创建 `student_correction`，再重新计算受影响窗口；旧 `state_series_snapshot` 标记为 `superseded`，不物理覆盖事件账本。
2. 动态自评到期后状态变为 `expired`，不能继续触发提醒、计划降载或向任何角色展示为“当前状态”；历史仅用于学生主动查看的回顾。
3. 系统无法确定状态时只显示“证据不足”，不得以默认值、缺失值或未登录行为填补。
4. 一项干预建议最多引用三个最相关证据，并必须标明事件日期、来源类型和适用范围；证据覆盖度低于 60% 时只允许询问，不允许展示趋势结论。
5. 学生关闭某个子变量的记录后，系统停止该子变量的新采集、趋势计算与主动询问；已经产生的数据按删除/保留授权策略处理。

#### 5.5.5 两周时间序列样例：把观察、推断与确认分开

以下是“函数图像与解析式转换”目标的两周样例。它说明系统如何支持自主调节，而不是从行为推断情绪。

| 日期 | 观察到的事实或学生确认 | 对应维度 | 系统可以说什么 | 系统不得说什么 |
|---|---|---|---|---|
| 第 1 天 | 学生将 30 分钟任务改为 20 分钟并确认 | `goal_planning`、`engagement_execution` | “你把任务调为 20 分钟，我会按这个时间安排。” | “你缺乏坚持力。” |
| 第 3 天 | 线下反馈：完成 12 题；两题在图像转换处出错；信心 3/5 | `cognition_strategy`、`motivation_affect.self_efficacy` | “这次在图像转换上有两条具体证据，下次可以先练对应关系。” | “你数学基础差。” |
| 第 5 天 | 学生选择“稍后”，未填写精力或感受 | `engagement_execution` | “要把今天的时间调整到明天，还是暂停本周任务？” | “你感到疲惫或不想学习。” |
| 第 7 天 | 周回顾：学生写“画图后再列式更容易”；计划合适度 4/5 | `monitoring_reflection`、`cognition_strategy` | “你找到了一种对自己有效的策略，下一周可以继续验证。” | “你已经完全掌握。” |
| 第 10 天 | 同类任务再次出现图像转换错因；信心 2/5 | `cognition_strategy`、`motivation_affect.self_efficacy` | “两个任务出现相同卡点，是否先做 15 分钟映射练习？” | “信心下降说明你很焦虑。” |
| 第 11 天 | 学生确认“今天有点累”，选择记录至当日结束 | `motivation_affect.energy_level` | “今晚改为 10 分钟复习或直接休息，选哪个？” | “你处于持续疲劳状态。” |
| 第 14 天 | 学生更正：第 10 天不是不会，而是题干读错 | `student_correction`、`cognition_strategy` | “已更新该次错因；我会重新计算图像转换的证据。” | “原有推断仍然成立。” |

在第 14 天重新计算后，系统若只剩两条相关错因证据，应将 `needs_consolidation` 降为 `evidence_insufficient`；若仍有至少三条来自两次任务的相关证据，才保留“建议继续验证”。这使状态变化可审计、可纠错、可复现。

### 5.6 从状态到教育支持：决策矩阵

| 五维状态组合 | 可解释判断 | 默认支持 | 学生可选项 | 不可做事项 |
|---|---|---|---|---|
| 目标清晰、执行不稳定 | 计划可能与时间窗或任务粒度不匹配 | 提供改期和 10 分钟起步任务 | 改时间 / 缩短 / 暂停 / 保持 | 不催促或扣减“自律分” |
| 执行稳定、知识证据不足 | 完成并不代表已掌握 | 添加低风险检查与错因反思 | 做 3 题检查 / 讲给 AI 听 / 暂不检查 | 不因完成率高直接提高难度 |
| 知识困难、信心下降 | 可能需要降低认知负荷 | 回退先备知识、换图示/实例、拆步骤 | 选一种策略 / 保持原题 / 稍后 | 不贴“基础差”标签 |
| 反思不足但任务完成 | 可能需要轻量脚手架而非长问卷 | 只问“下次保留什么、调整什么” | 语音 / 点选 / 跳过 | 不强制写长篇反思 |
| 自评疲劳或压力 | 当日支持强度可能过高 | 缩短、改期、休息或静默 | 休息 / 改期 / 继续但缩短 / 关闭提醒 | 不诊断心理问题、不转述给他人 |

### 5.7 学生可见的数字孪生界面

数字孪生面板必须展示“我能如何掌控系统”，而不展示抽象的学生评分：

- 本周目标和由学生确认的下一步；
- 五维状态的趋势词（如“证据不足”“较稳定”“需要一起调整”），不使用红黄绿人格化标签；
- 每个趋势的证据数、时间范围和“为什么这样判断”；
- “这不准确”更正入口、“不再记录此项”开关和历史数据查看入口；
- 以学科和目标为单位切换视图，默认不显示跨学科总分；
- 周回顾中先让学生自评，再展示系统汇总，避免系统替学生定义感受。

## 6. Multi-Agent 设计与协作协议

### 6.1 Agent 角色

| Agent | 输入 | 主要职责 | 输出 | 不可做事项 |
|---|---|---|---|---|
| Supervisor Agent | 孪生摘要、事件、规则、用户意图 | 判断当前是否需要行动，选择并调度子 Agent | 行动计划、需确认项、解释摘要 | 不绕过用户确认、不直接修改高影响状态 |
| 学习规划 Agent | 目标、水平、时间、可用资源 | 制定学习路线、拆解任务、滚动调整计划 | 阶段计划、任务、调整建议 | 不承诺提分、不生成不可执行的超量计划 |
| 陪伴沟通 Agent | 当前任务、偏好、提醒策略、状态摘要 | 主动启动、日常交流、鼓励、收集反馈 | 结构化交互请求、反馈摘要 | 不高频催促、不进行羞辱性比较 |
| 成长分析 Agent | 任务证据、作答、线下反馈、趋势 | 分析知识变化、习惯变化和学习风险 | 可解释洞察、置信度 | 不将推断描述为事实，不做心理诊断 |
| 干预策略 Agent | 洞察、目标、学生状态、策略历史 | 调整任务、难度、节奏或支持方式 | 可选策略及预期影响 | 不自动强制改计划，不惩罚未完成 |
| 安全与合规策略 | 内容、状态、权限、年龄段 | 内容过滤、频控、数据用途控制、风险升级 | 允许/阻断/人工转介建议 | 不替代专业机构处理高风险情形 |

### 6.2 决策流程

```text
事件进入（任务到期 / 学生反馈 / 线下完成 / 连续受阻）
  → L0 先落库 InteractionEvent / 更新任务状态 / 必要时立即打开 Modal
  → 读取最小必要的 StudentTwin 摘要缓存（非全量重算）
  → 路由：无需行动 / L1 轻量模板 / L2 深度编排 / 安全流程
  → 若 L1：本地或短调用生成“建议 + 理由 + 可选项”
  → 若 L2：创建 orchestration_job 异步执行，UI 显示进行中
  → 学生确认、拒绝、稍后或自行修改（不等待 L2 也可先改期/暂停）
  → 写入 InteractionEvent 与 Twin 更新记录
  → 必要时生成下一个任务或周期回顾
```

### 6.3 快慢路由与 Agent 调用预算

| 事件类型 | 默认路径 | 是否可升级 L2 | 说明 |
|---|---|---|---|
| 任务时间窗到达 | L0 + L1 模板启动询问 | 否（除非学生点“帮我重新安排”） | 主动提醒必须秒级出现 |
| 学生选择开始/稍后/暂停 | L0 状态机 | 否 | 只写事实，不推理情绪 |
| 任务反馈提交 | L0 写证据 + L1 规则洞察 | 命中连续困难/信心连续下降时升 L2 | 先回显“已收到反馈” |
| 连续受阻 / 节奏偏离 | L1 给出可选策略 | 学生点“看详细分析”或规则置信度不足时升 L2 | 不自动改计划 |
| 首周/下周计划生成 | L2 | 是 | 可显示骨架计划后异步细化 |
| 周/月回顾 | L1 事实汇总 + L2 解释文案 | 是 | 先展示学生自评与事实表 |
| 高风险表述 | L0 安全阻断模板 | 可异步补充转介文案 | 停止常规教育编排 |

**Agent 调用预算（MVP 硬约束）**：

1. 单次用户可见操作默认 **≤ 1 次完整 CN-Codex Agent 轮次**；能用规则/模板解决的不进 L2。
2. Supervisor 在 L2 内优先 **单 Agent 或“分析→干预”两步**，禁止默认五 Agent 全量串行。
3. 每个 `orchestration_job` 必须带：`job_id`、触发事件、预算（max_turns / timeout）、可取消标记、学生可见进度文案。
4. 超时或失败时降级：保留 L0 事实与 L1 模板建议，展示“这次没整理完详细分析，你可以先选改期/缩短/保持”。
5. 后台 job 不得在学生已暂停/静默后继续推送新的主动消息。

### 6.4 异步编排与 UI 不阻塞协议

```text
submit_event (L0 立即返回 accepted)
  → 若需要 L2：enqueue orchestration_job
  → UI：即时确认卡 + optional “正在整理建议…”
  → job 完成：推送可替换的结果卡 / InterventionProposal
  → 学生确认后才写回 plan / twin 高影响字段
  → job 过期、取消或被更新事件 supersede：结果丢弃或仅作历史
```

| 机制 | 要求 |
|---|---|
| 事件幂等 | 同一 `source_event_id` 不重复创建同类 job |
| 合并去抖 | 短时间多次反馈合并分析窗口（如 30–60 秒） |
| 取消与 supersede | 学生更正状态、暂停计划、撤回授权后取消未完成 job |
| 缓存摘要 | Agent 只读 `twin_summary_cache` 与最近 N 条证据，不每次全量扫描账本 |
| 预渲染 | 到点提醒、常见改期选项、休息选项在本地模板库预置 |
| 温度话术 | 温暖骨架模板 + 少量槽位填充；不因“更有温度”额外增加 Agent 轮次 |

### 6.5 可解释性要求

每次计划调整、难度变化或主动干预均应展示：

- **发生了什么**：例如“你最近两次任务均报告图像转换困难”。
- **系统如何理解**：例如“这可能意味着需要先强化图像与表达式的对应关系”。
- **建议做什么**：例如“明天先完成 15 分钟映射练习，再决定是否进入综合题”。
- **你有什么选择**：接受、改期、调整难度、保持原计划、关闭此类建议。
- **结果来自哪条路径**：L1 规则建议 / L2 深度分析（可折叠显示），避免学生误以为系统“瞬间读心”。

## 7. 核心功能需求

### 7.1 学生成长画像初始化

**目标**：首次使用时，以自然对话和可编辑结构化确认建立基础模型，而非使用考试式问卷。

**最小采集内容**：年级、主要学科、近期学习场景；长期/阶段/短期目标；可学习时间和节奏；偏好的讲解和反馈方式；学生愿意提供的自评信息。

**交互示例**：

> AI：如果半年后你希望自己有什么变化？
>
> 学生：数学提高 20 分。
>
> AI：我理解为“半年内提升数学成绩 20 分”。这个目标对你最重要的原因是什么？我们也一起确认每周能稳定安排的学习时间。
>
> AI：为了让目标可验证，我们可以把“提升 20 分”落成过程证据——比如“4 周内函数图像转换的错因再犯率下降”。你更愿意用哪种方式衡量做到了？

**验收标准**：初始化完成后，学生能看到画像摘要、编辑内容并确认“这是我当前的学习情况”；长期目标同时带有**成果目标**（如分数）与**可验证过程目标**（如错因率/完成率），后者进入后续周回顾的对比基线。

### 7.2 AI 学习规划系统

```text
目标 + 当前知识证据 + 时间条件 + 学生偏好
  → 阶段路线
  → 周计划
  → 可执行学习任务
  → 任务反馈
  → 滚动调整
```

示例：

```text
目标：数学提升20分
阶段1：基础漏洞修复
阶段2：重点知识强化
阶段3：综合训练
阶段4：模拟测试与错因复盘
```

**计划规则**：
- 每个任务必须定义目标、预计时长、建议时间窗、成功标准、反馈方式和可调整策略。
- 首周计划默认留出缓冲时间，避免排满。
- 系统提出调整，学生确认后才替换已确认计划；紧急暂停由学生自主操作。
- 未完成任务优先进入“原因理解”，不得默认归因为懒惰或能力不足。

### 7.3 学习任务管理系统

```json
{
  "id": "task_function_basics_001",
  "plan_id": "plan_math_term_1",
  "title": "二次函数基础：图像与解析式转换",
  "learning_objective": "能说出开口、对称轴和顶点与解析式的对应关系",
  "scheduled_window": "2026-08-01 20:00-20:30",
  "estimated_minutes": 30,
  "mode": "offline_practice",
  "status": "scheduled",
  "completion_evidence": [],
  "feedback_required": true,
  "adaptation_policy": "reduce_scope_then_retry"
}
```

任务状态：

```text
未开始 → AI 沟通 → 学生确认 → 执行中 → 反馈 → 分析 → 调整 / 完成
```

### 7.4 AI 主动教育交互系统

| 场景 | 触发条件 | AI 行为 | 学生可选项 |
|---|---|---|---|
| 学习启动 | 到达已授权的任务时间窗 | 询问是否开始，并允许调整 | 开始学习 / 稍后开始 / 调整时间 / 今天暂停 |
| 执行后反馈 | 任务结束或学生主动结束 | 询问完成、难点、信心与需要的支持 | 结构化选择、简答、语音转写、跳过 |
| 连续受阻 | 同知识点连续错误或两次反馈同一困难 | 提出换一种学习方式的建议 | 尝试新方法 / 保持原计划 / 稍后处理 |
| 节奏偏离 | 多次未开始、拖延或时长不匹配 | 不指责地询问时间安排是否不现实 | 改时间 / 缩短任务 / 暂停计划 / 不需要提醒 |
| 周期回顾 | 每周或每月，学生可配置 | 总结事实、呈现成长、邀请学生决策下一步 | 确认计划 / 调整目标 / 选择优先项 |

**频率规则**：默认每日主动学习消息不超过 2 次；同一任务最多 1 次启动提醒和 1 次结束反馈邀请。学生选择“稍后”后，在选定时间前不再催促；选择“今天暂停”后不再发送当日任务催促；可一键静默、设定免打扰时间和关闭某类主动建议。

### 7.5 线下学习闭环系统

```text
AI 制定线下任务
  → 学生在线下完成
  → AI 在约定时间主动或由学生主动反馈
  → 结构化记录完成情况、用时、困难、信心、可选作品证据
  → 更新 StudentTwin
  → 调整下一任务与策略
```

**线下反馈最小表单**：是否完成（完成/部分完成/未开始）、实际用时、最难部分、主观难度（1–5）、下次信心（1–5）、可选附件（经提醒脱敏后的作业局部，不要求上传）。

系统不得仅因“完成”就认定“掌握”，也不得仅因“未完成”就认定“缺乏意愿”。

### 7.6 五维学习状态采集与更新系统

本功能实施第 5.3–5.6 节的五维时间序列模型。采集遵循“**先让学生表达，再让系统建议**”：系统不会在后台推断学生情绪，也不将任务行为当作情绪事实。

| 触发节点 | 最多采集内容 | 写入维度 | 是否可跳过 | 更新规则 |
|---|---|---|---|---|
| 创建/调整目标 | 目标是否重要、可学习时间、学生想采用的计划方式 | `goal_planning` | 否，目标与时间窗的最小字段必填 | 由学生确认后写入稳定层；系统建议不直接覆盖 |
| 任务开始 | 是否开始、稍后、改期、暂停；可选精力 1 题 | `engagement_execution`、可选 `motivation_affect.energy_level` | 精力自评可跳过 | 开始/改期是任务事实；精力只在学生提交时写入且当日到期 |
| 任务结束 | 完成状态、实际用时、难点、难度、信心 | 五维中的相关子变量 | 除完成状态外均可跳过 | 每个回答绑定任务、学科和目标；未填字段不补零 |
| 学习过程检查点 | 作答、错因、所用策略、是否检查 | `cognition_strategy`、`monitoring_reflection` | 可选择稍后处理 | 只更新相关知识点和任务范围 |
| 周回顾 | 本周计划是否合适、有效策略、下周调整、可选目标价值 | 五维周级聚合 | 可将回顾改期 | 先显示学生自评，再显示系统的证据汇总 |

**对话文本处理规则**：模型可从学生主动输入的文本中提出“是否要记录为学习状态”的候选项，但必须显示原文摘要、拟记录字段和有效期，由学生点击确认。文本未经确认不得用于趋势计算，也不进入跨会话长期记忆。

**语音处理规则**：学生可在启用语音后使用“录音→转写→编辑→提交”。系统只处理学生最终提交的文本，不分析音色、语速、音量、停顿或任何声学特征；原始音频按最短必要期限删除。

**学习状态反馈示例**：

```text
AI：这项任务结束了。你希望简单记录一下现在的学习状态吗？
学生：有点累。
AI：是否记录为“今天精力：有点累”，仅用于把今晚的任务改轻一点？
    [记录到今天结束] [不记录]
```

如果学生点击“不记录”，AI 可以就当前对话作出一次性的回应，但不得在孪生中保留“疲劳”状态。

### 7.7 自主学习能力培养系统

| 能力 | 系统脚手架 | 逐步放手方式 |
|---|---|---|
| 目标管理 | 引导把愿望转为可衡量目标 | 从 AI 建议目标到学生自行提交目标 |
| 时间管理 | 推荐时间窗与缓冲任务 | 从默认排程到学生自行改排并复盘 |
| 自我监控 | 完成、难点、信心的简短反馈 | 从固定表单到学生自行选择记录重点 |
| 反思能力 | 周回顾中的“证据—原因—下一步”提示 | 从引导式问题到学生总结策略 |
| 策略调整 | 提供不同学习策略的可选项 | 从 AI 推荐到学生依据历史效果自主选择 |

**放手触发条件（量化门槛，补齐"何时减少介入"）**：

| 信号 | 门槛 | 系统动作 |
|---|---|---|
| 执行稳定 + 信心上升 | 连续 3 周执行率 ≥ 80% 且信心自评均值上升 | 主动提醒频率降半；开放"教练模式 / 自助模式"切换 |
| 自我监控成熟 | 连续 4 周反馈表单自愿填写完整率 ≥ 70% | 表单降为可选项，周回顾改为学生主导、AI 只做证据摘要 |
| 策略自选有效 | 连续 2 周学生自选策略后反馈"有效"占比 ≥ 60% | 干预建议从"推荐单选项"变为"仅呈现证据，由学生决策" |

> 放手是**渐进降介入**而非一次性关闭：任何降级动作需向学生说明原因、可回退，且学生主动决策次数进入成长报告。

## 8. 教学任务执行层：主链路与结构化交互

任务执行层服务于数字孪生和 Agent 闭环，避免系统退化为纯聊天陪读。

### 8.1 任务主链路

```text
热身 → 任务分析 → 知识点预览 → 理解与建模 → 练习 → 检查 → 迁移 → 反思
```

每一步都可映射到知识证据、策略证据或自我调节证据，并写回 StudentTwin。

### 8.2 Modal-first 交互原则

需要学生作出正式选择、输入、确认或自评时，使用教学交互弹窗，而不是要求学生在聊天框中猜答案格式。

| 类型 | 用途 |
|---|---|
| `choice` / `multi_choice` | 学习启动、策略选择、知识点识别 |
| `confirm` | 是否调整计划、是否进入下一阶段 |
| `text_input` / `textarea` | 反思、难点描述、学习策略记录 |
| `number` | 实际用时、自评量表 |
| `form` | 线下任务反馈、周回顾 |
| `voice_compose` | 语音作答后转写、编辑与确认 |

```text
Agent 发起结构化交互
  → EducationModal 打开
  → 状态 = awaiting_user_input
  → 学生提交 / 明确跳过 / 稍后处理
  → 记录 InteractionEvent
  → 才可进入分析或下一步
```

关闭但未提交不视为答错，不写入负向学情；学生可以稍后返回完成。

### 8.3 与中国 Codex 教育版的工程对齐

| 现有能力 | 教育系统复用方式 |
|---|---|
| `ApprovalModal` + `request_user_input` | 教学结构化输入与等待机制的交互范式 |
| `Sidebar` | 学习目标、计划与任务入口 |
| `ChatMessage` / 回显卡 | AI 解释、学生提交摘要、成长反馈 |
| `PlanCard` / `chat-work-card` | 学习计划、任务、阶段回顾的只读呈现 |
| 权限弹窗与审计机制 | 监护人授权、语音/附件授权、数据操作确认 |

### 8.4 顺畅执行：把慢速 Agent 从关键路径移走

教育体验必须以 L0/L1 保证“点了就有反馈”，CN-Codex 完整 Agent 轮次只承担 L2 深度任务。

| 学生动作 | 立即发生（L0/L1） | 可延后（L2） |
|---|---|---|
| 点“开始学习” | 任务变执行中、打开任务卡/计时、写入事件 | 无 |
| 点“今天暂停” | 当日催促关闭、温暖确认模板、状态更新 | 无 |
| 提交线下反馈 | “已收到”回显、证据落库、规则洞察候选 | 复杂错因关联与长解释 |
| 点“帮我重新安排” | 打开改期表单、显示骨架选项 | 完整周计划重排 |
| 到点提醒 | 本地模板弹窗 + 最新孪生摘要缓存 | 个性化长文鼓励（可选，不阻塞） |

**与 Modal 协议的关系**：

1. `awaiting_user_input` 只阻塞“下一步教学推进”，不阻塞“改期/暂停/关闭提醒”。
2. L2 进行中时，Modal 与任务列表仍可操作；新的学生动作可 `cancel` 或 `supersede` 旧 job。
3. 对话区允许出现“整理中”占位卡，但不得空白等待无反馈。

### 8.5 与中国 Codex 教育版的工程对齐（扩展）

| 现有能力 / 约束 | 教育系统用法 |
|---|---|
| Agent 轮次慢、工具链长 | 仅 L2 使用；设置 `max_turns` / timeout，失败降级 L1 |
| `request_user_input` / ApprovalModal | 作为结构化等待范式；教育侧自建 `EducationModalHost` 队列，不把每次选择都塞进完整 chat turn |
| 会话 JSONL 写盘 | 高频学习事件先写教育事件账本，再按需摘要进会话，避免每条反馈触发大上下文重放 |
| 工具搜索 / MCP 懒加载 | 教学主路径不依赖；学科包与规则本地化 |
| 线程上下文膨胀 | Agent 只注入 `twin_summary_cache` + 最近证据窗口，禁止整本 evidence_ledger 入 prompt |

## 9. 数据模型与事件设计

### 9.1 核心实体

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `student_twin` | `student_id`、状态摘要、版本、更新时间 | 学生数字孪生主记录 |
| `learning_goal` | 目标、周期、优先级、学生确认状态 | 长中短期目标 |
| `learning_plan` | 目标、阶段、计划窗口、状态、调整依据 | 可滚动学习计划 |
| `learning_task` | 任务、时间窗、时长、模式、完成标准、状态 | 线上或线下学习单元 |
| `interaction_record` | 触发原因、AI 消息、学生回应、同意状态 | 主动交互的可审计记录 |
| `learning_evidence` | 来源、内容摘要、关联知识点、可信度 | 作答、反馈、附件、教师授权证据 |
| `state_observation` | 维度、子维度、值、范围、来源、时间、有效期、授权引用 | 五维学习状态的不可变原子观测 |
| `state_series_snapshot` | 维度、窗口、趋势、波动、覆盖度、计算版本 | 学生可见的时间序列汇总，不替代原始事件 |
| `twin_update` | 前后状态、依据、置信度、可撤销性 | 画像变更记录 |
| `consent_record` | 授权范围、主体、时间、撤回状态 | 数据治理依据 |
| `state_inference` | 规则版本、候选结论、依据、覆盖度、确认状态 | 只能生成解释与询问，不能直接成为正式状态 |
| `student_correction` | 指向事件/快照、学生更正值、原因、提交时间 | 学生对状态和推断的可审计更正 |
| `voice_processing_log` | 授权、转写状态、确认状态、原始音频删除时间 | 证明语音只用于转写，不做声学或情感分析 |
| `orchestration_job` | job_id、触发事件、路径级别、预算、状态、结果摘要 | L2 异步编排任务；可取消、可 supersede |
| `twin_summary_cache` | student_id、摘要版本、窗口、生成时间 | 供 L1/L2 快速读取的最小孪生摘要，避免全量扫描 |

### 9.2 五维状态数据契约

所有动态状态写入统一的事件契约，确保一次“有点累”只在限定范围和限定时段内生效，且可以被学生撤回或更正。

```json
{
  "observation_id": "obs_20260727_001",
  "student_id": "stu_001",
  "dimension": "motivation_affect",
  "subdimension": "energy_level",
  "scope": {
    "subject": "math",
    "goal_id": "goal_math",
    "task_id": "task_function_basics_001"
  },
  "value": "a_little_tired",
  "value_scale": "enum:energized|normal|a_little_tired|want_to_rest",
  "source_type": "student_self_report",
  "source_event_id": "modal_submit_20260727_021",
  "captured_at": "2026-07-27T20:32:00+08:00",
  "expires_at": "2026-07-27T23:59:59+08:00",
  "confidence": "high",
  "consent_ref": "consent_learning_state_v1",
  "student_visible": true,
  "student_editable": true,
  "processing_version": "state-rules-v1"
}
```

字段约束：

- `dimension` 必须是五维之一；没有 `scope` 的观测不得写入跨学科“总体状态”。
- `source_type` 为 `system_inference_pending_confirmation` 时，`formal_state=false`、`eligible_for_trend=false`、`eligible_for_sharing=false` 必须同时成立。
- `expires_at` 为必填字段；任务感受最长 24 小时、精力最长当日结束、信心和目标价值使用窗口快照而不是无限期的当前标签。
- `consent_ref` 必须指向有效授权；授权撤回后，仅保留法律或安全要求的最小审计记录，所有新的观测和计算任务停止。
- 任何 API 返回给 Agent 的摘要必须剔除失效状态、未确认推断、已关闭子变量和超出当前 Agent 目的范围的数据。

`StateInference` 与 `StudentCorrection` 的最小契约：

```json
{
```

## 10. 典型干预策略

| 观察到的证据 | 系统假设 | 可选干预 | 学生控制权 |
|---|---|---|---|
| 同知识点连续错误 | 可能存在概念或表征障碍 | 回退基础、换示例、减少题量、请求教师帮助 | 选择其中一项或保持原计划 |
| 多次未按计划开始 | 时间窗或任务粒度可能不现实 | 改时间、缩短到 10 分钟、暂停、关闭提醒 | 不默认判定为拖延 |
| 任务完成但信心持续低 | 可能需要更多过程性反馈 | 增加示范、拆小步骤、先做低风险练习 | 可拒绝或只保留鼓励反馈 |
| 一段时间无学习证据 | 可能离线学习、计划失效或不希望被打扰 | 轻量询问近况、提供静默选项 | 不连续催促 |
| 学生明确表示疲劳或压力 | 当前支持强度可能过高 | 休息建议、减少负荷、改期、建议联系可信成年人 | 不进行心理诊断 |

## 11. 演示设计

### 11.1 5 分钟 Demo 脚本

| 时间 | 演示动作 | 评委应看到的能力 |
|---|---|---|
| 0:00–0:40 | 学生通过对话设定“半年数学提高 20 分”，确认每周可学习时间 | 自然建档与学生确认的数字孪生 |
| 0:40–1:20 | 展示画像页：目标、函数薄弱点、晚间可学习时间、信心自评，点击“为什么这么判断” | 动态、可解释、可修正的孪生 |
| 1:20–2:00 | 规划 Agent 生成阶段路线和本周任务，学生把任务由 30 分钟改为 20 分钟 | 个性化规划与学生控制权 |
| 2:00–2:40 | 到达时间窗，陪伴 Agent 发起启动弹窗；学生选择“开始学习” | 主动式交互而非被动问答 |
| 2:40–3:30 | 学生完成线下纸质作业后提交结构化反馈：完成、转换题困难、信心较低 | 线上线下一体化闭环 |
| 3:30–4:20 | 展示成长分析：关联连续困难证据；干预 Agent 推荐“映射练习 + 缩短任务” | 多 Agent 协作、可解释干预 |
| 4:20–5:00 | 学生确认调整；周报展示学习策略与自主决策成长；打开数据与提醒控制页 | 自主学习能力培养与合规控制 |

### 11.2 演示必须避免的误区

- 不将 AI 展示成直接给答案的题库。
- 不只展示聊天，不展示数字孪生更新依据和计划调整。
- 不将“主动提醒”演示成频繁催促。
- 不将学习状态展示成心理诊断或学生标签。
- 不忽略学生拒绝、暂停、改期、关闭提醒和删除数据的控制权。

## 12. 合规、安全与未成年人保护

### 12.1 数据与授权原则

- **最小必要**：仅收集完成学习支持所需的数据。
- **用途限定**：学习数据只能用于已告知的学习支持、必要运维和经授权的汇总分析。
- **分级授权**：对语音、附件、监护人共享、教师共享分别获取授权；未成年人按适用规则取得监护人同意。
- **可撤回**：撤回授权后停止新增采集和使用；按规则处理历史数据。
- **可访问与可更正**：学生/监护人可查看、导出、更正或申请删除个人数据。
- **默认保护**：语音、附件和敏感自评默认关闭或最小可见；不默认共享对话全文。
- **不采集被动生物信号**：不请求、不存储、不处理摄像头画面、人脸、眼动、姿态、微表情、声纹、语音音色/语速/停顿、键盘节律或其他可用于识别身心状态的被动数据。
- **语音最短处理**：语音仅在学生单次主动启用后用于转写；必须让学生编辑并提交转写文本，原始音频在转写成功或取消后立即删除，并写入 `voice_raw_audio_deleted` 审计事件；转写失败时不重试保留，除非学生重新主动录音。

### 12.2 教育内容与模型边界

- 不输出侮辱、歧视、羞辱、恐吓或诱导过度学习的内容。
- 对学科内容显示“学习辅助建议”，鼓励学生说明思路；重要结论提供来源或不确定性提示。
- 不承诺成绩提升，不制造“必须完成”的压力话术。
- 不以学习状态推断人格、家庭情况、心理疾病或价值判断。
- 不把在线时长、点击、改期、未完成、沉默或错误率作为情绪、动机、自我效能或心理状态的事实依据。
- 不使用情感识别、心理测评结论或生物识别模型为学生生成心理画像；`motivation_affect` 仅表示学生对当前学习任务的主动自评和经确认的学习感受。
- 涉及高风险情绪表达时，停止常规教育编排，提示联系监护人、教师、学校心理支持或当地紧急专业资源；系统不自行处置危机。

### 12.3 主动交互保护

| 风险 | 控制措施 |
|---|---|
| 过度打扰 | 频率上限、免打扰、稍后提醒、按任务窗触发 |
| 强制感 | 每次主动沟通提供跳过、改期、暂停和关闭入口 |
| 负向标签 | 区分事实/自评/推断；短期状态过期；学生可纠错 |
| 不透明调整 | 展示触发依据、建议和替代选项；重要调整需确认 |
| 数据越权 | 授权记录、角色权限、访问审计、数据导出与删除流程 |

### 12.4 合规验收清单

- [ ] 首次启用展示数据用途、授权范围和退出方式。
- [ ] 学生可关闭提醒、语音、附件与特定类别的主动建议。
- [ ] 画像页能展示关键状态来源、更新时间与可更正入口。
- [ ] 周报默认展示学习摘要，不默认暴露学生私密对话。
- [ ] 风险文案不构成心理诊断，具备人工/专业资源转介路径。
- [ ] 任何模型推断不直接作为惩罚、排名或高风险教育决策依据。
- [ ] 安全设计与接口日志均证明未接入摄像头、人脸、眼动、姿态、声纹或语音情感识别能力。
- [ ] 语音录入必须经过“启用→转写→编辑→提交”链路，且每段原始音频都有删除审计记录。
- [ ] 已失效的精力/任务感受状态不得出现在后续主动提醒、共享视图或 Agent 摘要中。

### 14.3 验收测试重点

1. 未提交结构化反馈时，系统不得假设学生已完成或自动推进任务。
2. 学生选择“今天暂停”后，系统当日不得继续推送任务催促。
3. 每次计划调整必须能回溯到明确事件、学生反馈或规则，并显示解释。
4. 学生更正学习状态后，后续主动沟通必须使用新状态。
5. 撤回语音/附件授权后，前端和服务端均停止新采集。
6. 连续困难触发的干预必须提供至少一个非惩罚性、可拒绝的选项。
7. 模型遇到高风险心理表述时，不得输出诊断或替代专业救助的结论。
8. 学生跳过精力、任务感受或目标价值自评时，系统不得写入默认负向状态或降低任何维度分值。
9. 连续改期、未登录、错误增多和在线时长只能更新执行或知识事实；测试必须证明它们不能生成 `motivation_affect` 观测。
10. 任一摄像头、人脸、眼动、姿态、声纹、语音副语言或键盘节律字段传入状态接口时，接口必须拒绝并产生安全审计记录。
11. 学生提交更正后，相关旧快照必须标记为 `superseded`，待发送的主动建议重新计算，过期建议不得继续发送。
12. 语音原始音频转写后必须删除；测试应检查删除审计事件存在，且 Agent 只能读取学生最终确认的文本。
13. 学生点击“开始/稍后/暂停/提交反馈”后，UI 必须在本地规则路径立即给出反馈；不得因 L2 Agent 未返回而空白等待。
14. 到点主动提醒默认走 L0+L1 模板；测试需证明不启动完整五 Agent 串行也能完成启动询问。
15. 同一 `source_event_id` 不得重复创建同类 `orchestration_job`；新反馈或学生更正必须能 cancel/supersede 旧 job。
16. L2 超时或失败时必须降级到 L1 可选项（改期/缩短/保持），并写入 `path_degraded_to_l1` 事件。
17. 注入 Agent 的上下文只能是 `twin_summary_cache` 与最近证据窗口，不得整本 evidence_ledger 入 prompt。

## 15. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 画像不准确 | 推荐失配、学生不信任 | 证据来源可见、置信度、学生更正、短期状态过期 |
| 主动交互过多 | 反感、依赖或焦虑 | 频控、静默、免打扰、明确拒绝路径 |
| 线下反馈失真 | 学情误判 | 使用多源证据、低置信度处理、不将单次反馈定性 |
| 模型幻觉 | 错误建议 | 模型输出限制为建议；关键计划动作经规则校验与学生确认 |
| 过度收集未成年人数据 | 合规与信任风险 | 最小采集、分级授权、可撤回、审计与删除机制 |
| 教育边界模糊 | 替代教师或心理诊断风险 | 明确辅助定位、教师协同、风险转介、禁止诊断 |
| CN-Codex Agent 轮次偏慢 | 主动陪伴卡顿、学生放弃反馈 | L0/L1/L2 分层；关键路径本地规则+模板；L2 异步可取消；超时降级 |
| 多 Agent 串行过重 | 时延叠加、上下文膨胀 | 默认单 Agent/两步编排；摘要缓存；调用预算与 job 合并去抖 |
| 温度话术依赖长推理 | “有温度”反而更慢 | 温度骨架模板库 + 槽位填充；不因共情额外增加 Agent 轮次 |

## 16. 最终定位与路演收束

**一句话**：

> 一个基于学生数字孪生的 AI 学习教练，通过长期主动陪伴、状态理解、线上线下闭环和动态教育干预，帮助学生形成自主学习能力。

| 普通 AI 陪读 | AI自主学习教练系统 |
|---|---|
| 提醒学习 | 在理解学生状态后，共同管理学习 |
| 回答问题 | 规划、陪伴、分析、干预形成闭环 |
| 关注完成 | 关注知识、习惯、策略和自主能力提升 |
| 只看应用内行为 | 连接线上任务与线下真实学习反馈 |
| 短期互动 | 基于学生确认的长期成长模型陪伴 |
| 学生依赖 AI | AI 逐步把目标、计划与反思的主动权还给学生 |

**路演结尾**：

> 我们不做一个催学生学习的机器人，也不做一个替学生回答问题的工具。
>
> 我们做一个会理解、会等待、会调整、也会逐步放手的 AI 学习教练。
>
> 它用学生数字孪生记住成长证据，用主动式 Agent 把计划变成行动，用线上线下闭环让真实学习被看见，最终帮助学生成为自己的学习管理者。

## 17. 学科包可插拔设计

### 17.1 设计目标

教育核心引擎（学生数字孪生、多 Agent 编排、任务闭环、授权与审计）保持学科无关；各学科以**学科包**形式提供教学内容资产，支持选择后自动启用、停用后可恢复，形成可插拔扩展能力。

| 决策项 | 第一期结论 |
|---|---|
| 扩展目标 | 内容可扩展：知识图谱、任务模板、错因分类 |
| 包粒度 | 学科级（如初中数学包），包内可按年级/章节组织 |
| 来源与安装 | 内置官方包；学生选择学科后自动启用 |
| 非目标 | 远程下载商店、第三方上传、包内可执行代码、完整题库/教材分发 |

设计原则：

- **学科不是硬编码**：数学、语文、英语等不写死在核心引擎中。
- **自动安装与启用**：初始化或设置中选择学科后，系统启用对应内置包。
- **隔离与安全**：每个包独立目录，仅含结构化 JSON/YAML 资源，不含可执行代码。
- **历史数据安全**：停用/卸载只影响新计划与新任务生成；不删除学生已有任务、证据与孪生记录。
- **上下文隔离**：与第 5 章一致，学科状态、知识证据与目标均按 `subject` 隔离，禁止跨学科总分。

### 17.2 逻辑关系

```text
通用教育引擎
├── 学生数字孪生 / Supervisor / 规划·陪伴·成长·干预 Agent
├── 任务状态机 / 结构化交互 / 授权审计
└── SubjectPackageRegistry（学科包注册与启用）
        │
        ├── junior-math（初中数学包）
        ├── junior-chinese（初中语文包）
        └── junior-english（初中英语包）
```

学生选择学科后的主路径：

```text
选择学科
  → 校验并启用内置学科包
  → 写入 student_subject_enrollments
  → 规划 Agent 读取该包知识图谱与任务模板
  → 生成该学科目标、周计划与任务
  → 反馈与错因写入该学科 scope 的孪生状态
```

#### 17.3.1 `manifest.json` 最小字段

```json
{
  "id": "junior-math",
  "name": "初中数学",
  "version": "1.0.0",
  "subject": "math",
  "stage": "junior",
  "grades": ["7", "8", "9"],
  "locale": "zh-CN",
  "description": "初中数学知识图谱、任务模板与错因分类",
  "resources": {
    "knowledge_graph": "knowledge-graph.json",
    "task_templates": "task-templates.json",
    "error_taxonomy": "error-taxonomy.json"
  },
  "compatibility": {
    "min_engine_version": "1.0.0"
  },
  "status": "official"
}
```

字段约束：

- `id` 全局唯一，建议 `{stage}-{subject}`。
- `subject` 为孪生、任务、观测统一使用的学科标识（如 `math`）。
- `resources` 指向包内相对路径；缺任一必需资源则启用失败。
- 第一期不支持包内脚本、自定义二进制工具或动态加载代码。

### 17.4 启用、停用与生命周期

#### 17.4.1 启用流程

```text
1. 学生在初始化或设置中选择学科（可多选）
2. SubjectPackageRegistry 扫描 education/subject-packs/
3. 按 subject 匹配官方包并校验 manifest 与必需资源
4. 写入 student_subject_enrollments（student_id, pack_id, subject, enabled_at, version）
5. 将包摘要注入规划 / 成长分析 / 干预策略 Agent 的最小上下文
6. 目标页、计划页、画像页按已启用学科筛选与切换
```

#### 17.4.2 停用 / 卸载规则

- 仅将对应 `student_subject_enrollments` 标记为停用或删除启用关系。
- **不删除**已生成任务、交互事件、StateObservation、知识证据与周回顾记录。
- 停用后：不再为该学科生成新计划或主动任务；历史视图仍可按授权查看。
- 再次启用时：沿用学生既有孪生与证据，按当前包版本继续规划。

#### 17.4.3 版本与兼容

- 包使用语义化版本；启用时记录 `pack_version`。
- 引擎升级后若 `min_engine_version` 不满足，禁用该包并提示“需要更新系统后再启用”。
- 第一期不做在线热更新；内容更新随产品发布替换内置包目录。

### 17.5 与现有架构的集成

| 模块 | 集成方式 |
|---|---|
| 学生数字孪生 | 目标、知识状态、五维观测均带 `scope.subject`；仅已启用学科可进入新目标创建 |
| 规划 Agent | 只读取已启用包的知识图谱与任务模板生成阶段/周计划 |
| 陪伴 Agent | 任务启动与反馈字段可引用包内错因分类与交互提示 |
| 成长分析 Agent | 连续困难、错因聚合限定在同一 `subject` 与知识节点 |
| 干预策略 Agent | 降阶、换表征、缩时等策略优先映射包内 `default_strategy` |
| 初始化画像 | “主要学科”选择即触发包启用；未启用学科不出现在默认计划中 |
| 前端学科切换 | 画像与计划默认按学科视图展示，不显示跨学科总分 |

建议新增编排能力（概念接口）：

| 接口 | 作用 |
|---|---|
| `edu_list_subject_packs` | 列出内置可用学科包 |
| `edu_enable_subject_pack` | 启用学科包并写入 enrollment |
| `edu_disable_subject_pack` | 停用学科包（保留历史） |
| `edu_get_subject_pack_context` | 获取某学科最小知识/模板/错因摘要供 Agent 使用 |

### 17.6 与 MVP / 复赛 / 决赛范围的关系

| 阶段 | 学科包范围 |
|---|---|
| Phase 1 MVP | 1 个官方学科包（建议 `junior-math`）+ 选择启用闭环 + 3 个真实任务模板与 Demo 数据 |
| Phase 2 复赛 | 包内知识图谱与错因分类更完整；画像/计划按学科切换稳定 |
| Phase 3 决赛 | 多学科官方包并行；可选跨学科任务包；仍不默认开放第三方任意代码包 |

### 17.7 验收要点

1. 未启用某学科包时，系统不得生成该学科新计划或新任务。
2. 启用 `junior-math` 后，初始化与规划流程可读取其知识节点与任务模板。
3. 停用学科包后，历史任务与证据仍可查看，但不再推送该学科新任务。
4. 包缺少 `manifest` 或任一必需资源时，启用失败并给出可理解错误，不得部分写入。
5. 任一学科观测与知识状态必须带 `subject`；不得因多包并存产生跨学科总分。
6. 学科包目录中不得加载或执行自定义代码入口。

### 17.8 非目标（第一期明确不做）

- 远程学科包商店、自动下载与付费分发。
- 教师/机构自由上传未审核包。
- 包内注册任意 Agent 工具或前端自定义组件。
- 以教材版本为唯一安装粒度（可作为包内标签，不作为第一期安装单位）。
