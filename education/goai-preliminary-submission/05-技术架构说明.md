# 技术架构说明

## 1. 架构目标

1. **孪生可生长**：多源证据持续更新，覆盖度可见  
2. **计划可动态**：调整建议绑定孪生快照与学生确认  
3. **采集可接受**：心理学友好话术与跳过/更正路径内建  
4. **内容可追溯**：题目/答案键/解析/掌握证据有明确出处  
5. **纸质优先**：默认 offline_paper 任务 + 作业照片证据；屏上题库非主路径  
6. **任务闭环可运行**：从输入到结果交付全链路可演示  
7. **体验顺畅**：关键路径本地即时，深度分析异步  
8. **可选姿态增强**：手机端类别化信号进入编排，默认可关  
9. **合规内建**：授权、最小化、审计不是后贴

## 3. 分层职责

| 层级 | 职责 | 关键约束 |
|---|---|---|
| 交互层 | 任务列表、对话、弹窗、回顾、授权设置 | 重要输入结构化；确认后再生效 |
| 交互层（手机） | 姿态辅助开关与提醒 | 默认关；可忽略单次提醒 |
| 编排层 | 路由、状态机、频控、job 队列 | 高影响变更需确认；可取消 |
| Agent 层 | 规划/陪伴/分析/干预/安全 | 默认最小调度，禁全量串行 |
| 孪生层 | 生长模型、覆盖度、摘要 | 事实/自评/推断分层；驱动动态计划 |
| 知识层 | 学科包资源 | 无包内可执行代码 |
| 数据层 | 事件、授权、审计 | 最小化、可导出删除 |
| 模型层 | LLM/STT/姿态估计 | 可插拔、可降级；姿态端侧优先 |

## 4. 运行时路径

### 4.1 L0 即时路径

```text
click/timer → validate consent → write event → update task FSM
→ open modal / show toast → return accepted
```

### 4.2 L1 轻量路径

```text
event + twin_summary_cache → rule/template → options + short reason
→ UI render suggestion card / modal fields
```

### 4.3 L2 深度路径

```text
enqueue orchestration_job(budget, cancelable)
→ agent turns with tools (bounded)
→ result card replace placeholder
→ wait student confirm for high-impact writes
→ on timeout/error: degrade to L1
```

## 5. 与 CN-Codex 工程对齐

| CN-Codex 能力 | 教育系统用法 |
|---|---|
| Agent 多轮 tool call | 仅 L2；设 max_turns/timeout |
| `request_user_input` / ApprovalModal | 结构化等待范式参考 |
| Sidebar / ChatMessage / PlanCard | 任务入口、回显、计划呈现 |
| 会话 JSONL | 高频学习事件先写教育账本，再摘要进会话 |
| 工具搜索 / MCP 懒加载 | 教学主路径不依赖 |
| 本地配置与权限弹窗 | 监护人/语音/附件授权复用思路 |

**性能策略**：禁止每次反馈全量回放大上下文；Agent 只读 `twin_summary_cache` + 最近 N 条证据。

## 6. 核心状态机

### 6.1 任务状态

```text
scheduled
  → proactive_prompted
  → confirmed | postponed | paused_today
  → in_progress
  → feedback_pending
  → analyzing
  → completed | adjusted
```

### 6.2 弹窗等待

```text
idle → awaiting_user_input → validating → idle
```

### 6.3 Job 状态

```text
enqueued → running → completed | failed | cancelled | superseded
```

## 7. 数据存储建议（MVP）

```text
education/data/
  student_data/           # twin, plans, tasks
  events/                 # interaction & system events
  subject-packs/          # built-in packs
  templates/              # proactive / warmth templates
  demo/                   # sample student & tasks
```

存储原则：

- 本地文件/嵌入式存储优先  
- 事件不可变追加；快照可 `superseded`  
- 密钥与模型配置走现有 CN-Codex 配置体系  

---

## 8. 安全架构要点

1. 所有写高影响字段路径经确认或明确规则  
2. Safety Agent/规则在内容出口前过滤  
3. 授权失败时 L0 直接拒绝采集  
4. 导出/删除为显式用户操作并审计  
5. 模型网关对 prompt 做最小化与脱敏  
6. 学科包仅加载声明资源，不 `eval` 包内代码

## 11. 技术选型原则（不绑定单一厂商）

- **框架**：可基于 CN-Codex 现有 Agent 运行时扩展；不强制外部 Agent 平台  
- **模型**：开源/商业均可，需可替换  
- **知识**：本地学科包 RAG/规则检索，先规则后生成  
- **语音**：可选 STT/TTS，失败降级纯文本  

---

## 12. 架构质量要求

架构以清晰的模块边界、明确的 L0/L1/L2 时延分层、完整的任务数据闭环、安全可插拔的学科包与可见的合规控制点为质量基线，可据此拆分工程任务。
