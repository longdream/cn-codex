# API 接口测试 Skill

## 用途

输入 Swagger/OpenAPI 规范的 JSON/YAML 地址（或本地文件路径），自动完成以下步骤：

1. 解析 API 规范，提取所有路径、方法、参数、请求体 schema
2. 根据 schema 自动生成合理的 mock 请求数据
3. 逐个发送 HTTP 请求进行接口测试
4. 收集响应状态码、响应时间、返回结构校验结果
5. 输出 Markdown 测试报告

## 使用方式

在对话中调用本 Skill 时，助手应执行以下步骤：

### 第一步：读取本 Skill 文件

```markdown
读取 SKILL.md 了解完整流程。
```

### 第二步：检查环境依赖

确保 Python 环境中已安装以下依赖（如未安装则自动安装）：

```bash
pip install requests pyyaml jsonschema
```

### 第三步：收集用户输入（必须执行）

**在任何测试执行之前，必须向用户确认以下参数，并等待用户回复全部或部分参数。** 不允许直接使用默认值跳过用户确认。

- **Swagger 地址**：OpenAPI 规范的 URL（例如 `https://petstore.swagger.io/v2/swagger.json`）或本地文件路径。用户已提供时可直接确认。
- **Base URL**（可选）：覆盖规范中的 `servers` / `host`，默认使用规范中的值。用户可留空。
- **需要测试的路径**（可选）：留空则测试所有路径；支持逗号分隔，如 `/pet,/store`。用户可留空。
- **请求头**（可选）：全局自定义 Header，如 `Authorization: Bearer xxx`。用户可留空。
- **超时时间**（可选）：每个请求的超时秒数，默认 30。用户可留空。

确认格式示例：
> 请确认以下参数（可留空使用默认值）：
> - Base URL（默认：https://petstore.swagger.io/v2）
> - 测试路径（默认：全部）
> - 请求头（默认：无）
> - 超时时间（默认：30秒）
> 请回复您的选择，或回复“全部使用默认值”。

### 第四步：运行测试脚本

#### 4.1 生成命令

根据用户确认的参数，生成如下可执行命令。**脚本路径请提示用户根据实际存放位置调整**，默认假设脚本位于当前工作目录下的 `scripts/api_test_runner.py`，用户可替换为实际路径。

```bash
python scripts/api_test_runner.py \
  --spec <SWAGGER_URL> \
  --base-url <BASE_URL> \
  --paths <PATH_FILTERS> \
  --headers <HEADERS> \
  --timeout <TIMEOUT>
```

#### 4.2 执行方式

- **如果助手当前环境可以执行 Python 脚本（例如具备 shell 执行权限）**，则直接运行该命令，并捕获输出。
- **如果无法执行（例如在受限对话环境）**，必须明确告知用户：“当前环境无法自动执行脚本，请手动在您的终端中运行以下命令（需要先安装依赖）”，然后提供完整命令，并说明脚本位置。
- 无论哪种情况，都需要确保用户知道如何获得测试报告（脚本执行后会在同一目录下生成 `test_report.md`）。

### 第五步：输出测试报告

脚本执行完毕后，将 Markdown 测试报告写入 `scripts/test_report.md`。助手应读取该文件并展示给用户，内容包括：

- 测试概况（总接口数、成功数、失败数、平均响应时间）
- 每个接口的详细测试结果（路径、方法、状态码、响应时间、结构校验是否通过）
- 失败的接口及其错误详情
- 建议与风险提示

**注意：** 报告中的接口数量应基于实际解析的规范路径数，与用户期望及 Swagger 文档一致。如果数量不符，应在报告中注明解析结果。

## 注意事项

- 只测试 GET 请求时不会修改服务端数据；POST/PUT/DELETE 等操作会实际影响数据，请提前告知用户风险
- 自动生成的 mock 数据可能不符合业务语义，建议用户在关键接口上提供自定义请求体
- 如果规范需要认证（API Key / OAuth2），用户需提前提供有效的认证凭据
- 脚本路径 `scripts/api_test_runner.py` 仅为示例，实际位置请用户根据仓库结构自行调整。建议在运行前确认文件存在
