# 招标文件解析

## 目标
- 根据用户指令解析指定文档，支持 Word/PDF（`doc/docx/pdf`）。
- 必须提取并输出关键信息，尤其优先覆盖废标项。
- 输出必须包含：`信息分类 + 数量 + 内容 + 章节定位`。

## 对外输出要求（必须）
- 面向客户输出时，必须使用通俗中文，优先描述“结论与影响”，不要暴露技术实现细节。
- 禁止在对客文本中直接出现以下术语或同类内容：
  - `query_route.json`、`source.md`、`chunks.json`、`artifact_dir`
  - `mode=chunks`、`mode=source`、`retrieval_hits_json`、`token_estimate`
  - `cache hit/miss`、`generated_at`、脚本绝对路径
- 如需描述执行过程，统一改写为业务话术，例如：
  - “已重新读取并按章节核对文档”
  - “已完成重点条款检索和交叉验证”
  - “已补充全局复核”
- 对客语言自检（强制）：
  - 不输出 JSON、代码块、命令行、脚本路径、内部字段名。
  - 不解释底层检索实现，只说明“已核对哪些条款、结论是什么”。
  - 输出必须让非技术人员直接看懂，不需要任何系统背景知识。
  - 定位信息禁止出现 `P\d+`、`(P\d+)`、`第X页` 这类页码样式；仅允许章节名或“章节未定位”。

## 强制提取范围
- 项目名称
- 招标编号
- 保证金信息（金额、支付方式、支付账号、开户行、户名等）
- 废标项（含一票否决项）
- 投标截止时间
- 开标时间
- 投标地点
- 企业资质要求
- 人员资质要求
- 技术参数要求
- 商务条款
- 评分标准（含分值占比/权重）
- 标书结构要求
- 密封要求
- 企业内法务及 BC 管理重点关注信息
- 其他未列出但招标文件明确要求的重要信息（补充项）

## 废标项识别规则
- 自动识别并提取包含以下关键词的条款：
  - `一票否决`
  - `无效投标`
  - `不予受理`
  - `废标情形`
  - `否决投标`
- 废标项是最高优先级类目，必须给出清晰章节定位。

## 强制规则
- 文档长度 `<=10000`（字符估算）时：直接整文执行本地规则提取，不执行召回策略。
- 文档长度 `>10000` 时：执行分层检索策略：
  1. 先定位候选章节（章/节/条/款/项）
  2. 在候选章节内做关键词细节召回（段落级）
  3. 若仍无命中，使用 `AskUserQuestion` 询问是否全局搜索
  4. 用户同意后执行全局搜索

## OCR 规则
- 对 PDF/Word 中图片与扫描页自动触发 OCR。
- OCR 结果必须按原文结构位置归位回填（不能统一追加文末），并参与后续信息提取与分块。

## 错误提示规则（必须原文）
- 上传非指定格式文件：`不支持该格式文件，请上传.doc/.docx/.pdf 格式文件`
- 文件加密无法解析：`文件已加密，请解密后重新上传`
- 文件损坏无法读取：`文件损坏，无法解析，请检查文件后重新上传`

## 执行方式
### 远程服务地址配置（强制）
- 执行前先编辑 `tender-document-parsing/.skill.env`，并设置：
  - `BID_API_BASE=http://10.136.0.123:10104`
- 仅允许远程地址，禁止使用 `localhost` / `127.0.0.1` / `0.0.0.0`。
- 若配置为空或填写本地地址，脚本会直接报错，不再回退到本地端口。

### Bash/Shell 超时配置（强制）
- 本 Skill 中所有 `python scripts/*.py` 命令都必须通过 Bash/Shell 工具执行。
- 执行时必须显式设置：`block_until_ms: 3600000`（1 小时）。
- 该规则覆盖本节全部命令场景：常规执行、`--force-refresh`、带 `--instruction`、`--enable-global-search`、`--api-base` 临时覆盖。
- 禁止省略该参数或使用默认超时，避免长文档解析中途被工具层超时打断。

Shell 调用示例（所有 Python 命令同理）：
```json
{
  "command": "python scripts/call_extract.py --file \"ABSOLUTE_FILE_PATH\"",
  "block_until_ms": 3600000
}
```

### 常规执行（允许缓存复用）
```bash
python scripts/call_extract.py --file "ABSOLUTE_FILE_PATH"
```

### Windows 终端执行约束（强制）
- 必须优先使用上面的 `call_extract.py` 单命令执行，不要改用临时 `python -c` / 临时脚本拼接处理结果。
- 当 `call_extract.py` 已返回成功 JSON 时，不要再二次读取 `result_extract.json` 做重复加工；直接基于返回结果组织对客结论。
- 该脚本已内置 UTF-8 输出兜底，不需要额外手工设置 `PYTHONIOENCODING` 才能运行。

### 再次读取/读取最新（强制刷新，必须）
- 当用户明确要求“再次读取 / 重新读取 / 读取最新 / 按最新文件重跑”时，必须追加 `--force-refresh`。
- `--force-refresh` 会跳过历史缓存并重新解析文档，避免文档已更新却继续使用旧产物。

```bash
python scripts/call_extract.py --file "ABSOLUTE_FILE_PATH" --force-refresh
```

带补充指令：
```bash
python scripts/call_extract.py --file "ABSOLUTE_FILE_PATH" --instruction "重点提取废标项、保证金、评分标准"
```

用户确认全局搜索后再次执行：
```bash
python scripts/call_extract.py --file "ABSOLUTE_FILE_PATH" --instruction "..." --enable-global-search
```

临时覆盖接口地址（仅本次命令）：
```bash
python scripts/call_extract.py --file "ABSOLUTE_FILE_PATH" --api-base "http://10.136.0.123:10104"
```

说明：服务端仅承担 OCR（及可选 embedding）能力；key_info 提取在本地脚本完成。

## 输出格式要求（强制）
- 输出样式可灵活，但每个分类必须包含：
  - 分类名称
  - 分类数量（N个）
  - 条目内容（编号列表）
  - 条目章节定位（如 `文件【合同条款点对点应答】`）
- 对客回复中不得出现中间产物字段名、内部文件名或检索模式名。
- 对客最终文本必须是业务结论，不得直接粘贴内部原始结构（如调试字段、路径信息、执行参数）。
- 若条目原文末尾包含目录页码噪声（如 `（P2200）`、`......2200`），对客输出前必须剔除该噪声再给结论。
- 定位字段只允许“章节名”；无法确认章节时统一输出“章节未定位”，不得输出任何页码索引。
- 推荐表达方式：
  - `“{项目名称}”文档作为招标文件的关键信息提取如下：`
  - `废标项（2个）1.xxx，文件【合同条款点对点应答】；2.xxx，文件【投标人须知】；`
  - `投标截止时间（1个）1.xxx，文件【投标函】；`
  - `开标时间（1个）1.xxx，文件【开标安排】；`
  - `投标地点（1个）1.xxx，文件【投标人须知】；`
  - `评分标准（1个）1.xxx，文件【评分标准】；`
- 对“其他重要信息”单独输出为“补充重点（N个）”。

## 结果校验
- 强制提取范围中的分类均已出现（可为 0 个，但不能缺类）。
- 废标项关键词命中结果已覆盖。
- 保证金信息尽量覆盖金额、支付方式、支付账号等细节。
- 评分标准尽量覆盖分值占比/权重信息。
- 每条信息必须带章节定位；无法定位时需明确标注“章节未定位”。
