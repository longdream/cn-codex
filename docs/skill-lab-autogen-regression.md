# Skill Lab AutoGen 回归清单

## 目标生成链路
- [ ] 无 Python 环境时，点击“自动生成”应提示安装引导，不发起生成。
- [ ] 自动生成配置可独立选择供应商、模型与本地知识库开关；首次进入默认使用主对话当前供应商/模型，知识库默认关闭。
- [ ] 切换生成供应商时模型自动切到该供应商首个可用模型；无有效模型时“自动生成”不可点击。
- [ ] 启动生成后再修改生成配置或全局模型，不影响已经启动任务使用的运行快照。
- [ ] 有 Python 环境时，输入目标后可自动生成 `SKILL.md` 与 `scripts/*.py`。
- [ ] 开启生成知识库后可利用相关召回内容；索引缺失或无命中时仍能继续生成。
- [ ] 最终 Skill 仅在目标确需部署后动态检索时包含通用 `smartbrain_search` 规范，不应机械依赖知识库。
- [ ] 生成完成后，草稿列表和详情页中的 `name/content/testPrompt` 自动刷新。
- [ ] 生成后的 skill 名称应为标准英文 kebab-case（如 `stock-evaluation`），而不是 `lab-时间戳`。
- [ ] 非法脚本路径（如 `../x.py`）或空脚本应被后端拒绝并返回可读错误。

## 自动进化链路
- [ ] 迭代进化配置可选择与生成阶段不同的供应商、模型与本地知识库开关。
- [ ] 切换 Skill 草稿不会改变生成或迭代配置；重新打开实验室可恢复最近选择，但偏好中不包含 API Key。
- [ ] 启动迭代后再修改迭代配置或全局模型，不影响已启动任务使用的运行快照。
- [ ] 只有 `failed` 且最近 AI 评估非空的 Skill 在列表中显示“需要改进”；未测试和已通过 Skill 不显示。
- [ ] 点击“需要改进”的 Skill 只打开详情并带入格式化后的改进要求，不应立即发起模型调用。
- [ ] 改进要求可编辑；为空时“一键改进”不可点击，确认后才启动现有测试、评估、改写闭环。
- [ ] “一键改进”把同一固定要求注入测试、评估和改写三阶段，并继续使用当前迭代供应商、模型、资源池与知识库快照。
- [ ] 一键改进通过后列表标识和详情改进面板消失；仍未通过时按最新 AI 评估刷新改进要求并可再次运行。
- [ ] 点击“运行测试”后，阶段顺序保持 `testing -> evaluating -> rewriting -> done`。
- [ ] 普通“运行测试”不携带改进要求，消息结构和原有行为保持不变。
- [ ] 开启迭代知识库后，测试、评估和改写使用同一轮不可信参考上下文；进度日志只显示命中数量，不显示召回正文。
- [ ] 知识库关闭、索引缺失或无命中时，测试、评估和改写保持原流程并继续运行。
- [ ] 评估结果应包含多维分数（clarity/robustness/executability/maintainability/total）。
- [ ] 达到高分且进入平台期后自动停止；未达标时最多迭代到上限。
- [ ] 最终落盘内容应使用最佳分版本，而非最后一轮版本。

## 推广链路
- [ ] 推广后 `codey/skills/<标准skill名>/SKILL.md` 存在，且目录名不是 `lab-*`。
- [ ] 推广后 `codey/skills/<标准skill名>/scripts/` 与实验室草稿目录保持同步。
- [ ] 推广后 `SKILL.md` 具备可用 frontmatter（至少 `name/description`）。
- [ ] 推广后 frontmatter 的 `name` 与正式 skill 目录名一致（标准英文 kebab-case）。
- [ ] 推广后无需重启应用，对话 `+ / 添加 Skill` 与 Skills 面板可立即看到新 skill。
- [ ] 实验室 `meta.json` 和推广目录中不存在 provider/model/runtimeConfig/smartbrainEnabled/API Key 等实验室运行配置。
- [ ] 实验室 `meta.json`、`SKILL.md` 和推广目录中不存在请求级 `improvementRequest`。

## LLM 传输一致性
- [ ] provider 的 `http_headers` 能注入到请求头。
- [ ] provider 的 `query_params` 能追加到请求 URL。
- [ ] 主循环外流式解析在 `responses/anthropic/gemini` 下能正常提取文本。
