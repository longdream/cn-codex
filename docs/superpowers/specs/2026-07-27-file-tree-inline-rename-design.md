# 文件树原位重命名设计

## 目标

将右侧文件树的“重命名”从浏览器原生 `window.prompt` 改为与 VS Code 一致的原位编辑体验，消除与应用主题不一致的系统弹窗。

## 范围

- 仅改造已有文件或文件夹的“重命名”动作。
- 入口仍为文件树右键菜单的“重命名”。
- 不改变创建文件、创建文件夹与删除等其他动作的现有交互。

## 交互设计（已确认：方案 1）

1. 用户在文件或文件夹的右键菜单中点击“重命名”。
2. 当前树节点保留原有图标和缩进，仅名称文本替换为原位输入框。
3. 输入框自动聚焦，并选中当前完整名称，用户可立即覆盖输入。
4. 用户按 `Enter`：
   - 去除首尾空白；
   - 空名称或名称未变化时，结束编辑且不调用重命名接口；
   - 其他名称调用既有 `renamePathEntry`，成功后刷新文件树。
5. 用户按 `Escape`：结束编辑并恢复原名称，不调用重命名接口。
6. 方案 1 不处理点击树外取消；输入框持续显示，直到用户按 Enter 或 Escape。
7. 后端调用失败时复用已有 `actionError` 错误展示；编辑状态结束，文件树维持原内容。

## 状态与实现边界

- 在 `FileTree` 组件新增一个受控的编辑状态，包含目标节点路径与输入值。
- 以节点完整路径识别正在编辑的条目，防止同名条目互相影响。
- 将现有重命名回调拆分为“开始编辑”和“提交重命名”：上下文菜单只开启编辑状态；提交时才调用 API。
- 文件树节点渲染根据编辑状态在静态名称与 `<input>` 间切换。
- 输入框的样式沿用侧栏现有颜色、字号和行高，并确保其宽度不破坏文件树的图标、缩进及操作区域。

## 验收条件

- 点击“重命名”不再触发 `window.prompt`。
- 目标条目名称原位成为已聚焦、内容全选的输入框。
- Enter 可提交有效的新名称并刷新树；空名称与原名称不产生 API 调用。
- Escape 取消且不产生 API 调用。
- 文件与文件夹均支持此行为。
- TypeScript 构建和相关测试通过。
