# AI 自主学习教练系统教育版产品设计

> **实施状态（2026-07-31）**：桌面三栏主链路、首次建档向导、左右栏真实数据层、Android 配套端 MVP 已在 `cn-codex-edu` 落地；文生图、插件管理、Skill 实验室、机器人、自动更新、运势推算已从教育版移除；Skills 按 7.2 白名单完成裁剪。细节见 3.3.1、3.3.2 与第 10 节。

## 1. 目标与范围

本设计定义 AI 自主学习教练系统的教育版桌面端与 Android 配套端。教育版以 CN-Codex 的稳定交互基础为参考，但作为独立项目维护；本阶段仅形成产品、架构、数据与合规设计，不修改 CN-Codex 工程代码。

### 1.1 产品目标

1. 让学生以纸质材料为主要学习媒介，在桌面端获得任务、对话、成长反馈与动态计划支持。
2. 以 Android 端提供语音陪伴、姿态辅助与试卷采集，减少学生在桌面端操作的负担。
3. 让数字孪生、学习证据、知识掌握和计划调整在可解释、可更正、可撤回的前提下形成闭环。
4. 复用成熟的对话、任务、弹窗、权限和本地存储思路，同时移除与 AI+教育无关的开发功能。
5. 控制模型调用次数与上下文体积，避免无关工具、代码上下文、全量聊天记录和原始视频增加 Token 消耗。

### 1.2 非目标

- 不在现有 CN-Codex 主工程中直接删除或重写代码开发链路。
- 不把教育版定位为代码编辑器、终端、项目管理器或通用 Agent 开发平台。
- 不进行身份识别、人脸特征建模、情绪读心、持续视频云端上传或监控式摄像。
- 不以长期屏上刷题、题库连刷或自动给出完整答案作为主学习路径。
- 不提供心理疾病诊断、医疗意见、自动化惩罚、排名或升学判断。

## 2. 项目形态与裁剪策略

### 2.1 独立教育版项目

教育版采用“同源能力参考、独立项目交付”的策略：建立一个与 CN-Codex 产品结构相近的教育应用，而不是在原应用主链路上叠加大量教育分支。

| 类别 | 教育版策略 | 原因 |
|---|---|---|
| 对话流、消息渲染、结构化弹窗 | 复用交互范式 | 保持成熟、顺畅的对话体验 |
| 左侧列表与任务状态 | 改造成学习任务入口 | 直接服务每日学习闭环 |
| 本地配置、授权与数据存储 | 复用本地优先原则 | 支持未成年人数据最小化与可删除 |
| 工作区、文件树、终端、代码编辑 | 不进入教育版 | 与学习主链路无关，增加界面和模型负担 |
| 代码生成、补丁、调试、测试、代码审查 | 不进入教育版 | 不符合 AI+教育的主产品定位 |
| MCP 开发、插件开发、开发类 Skills | 不进入教育版默认能力 | 避免暴露复杂开发入口与无关工具定义 |
| 小程序能力 | 保留为“学习小工具” | 支持学生创建闪卡、计时器、错题整理、知识复习工具 |
| 通用工具调用 | 按教育任务白名单启用 | 降低工具描述、调用链和 Token 消耗 |
| 文生图、插件管理、Skill 实验室、机器人、自动更新、运势推算 | 不进入教育版（已移除） | 与学习主链路无关，已从前端设置、装配与相关代码中清除 |

### 2.2 主链路稳定性

教育版保留“左侧任务—中间对话—右侧信息面板”的稳定主链路，但替换其业务语义：

```text
学习任务选择或到点提醒
  → 中间对话引导与结构化确认
  → 纸质学习或手机端采集
  → 证据写入与成长摘要更新
  → 右侧面板呈现掌握、节奏和建议
  → 学生确认动态计划调整
```

教育功能不得通过新增多层全局 Agent、全量工具清单或每次操作均调用大模型来改变主链路性能。所有高成本能力都必须在教育编排层按需调用。

## 3. 桌面端体验设计

### 3.1 信息架构

| 区域 | 名称 | 核心内容 | 设计原则 |
|---|---|---|---|
| 左侧 | 学习任务栏 | 今日任务、即将开始、暂停任务、材料进度、周期回顾 | 一眼知道下一步，不展示项目与代码信息 |
| 中间 | 学习对话区 | AI 陪伴对话、语音转写、学习引导卡、拍照/OCR 结果、结构化确认弹窗 | 保持熟悉对话体验，关键状态不靠自由文本猜测 |
| 右侧 | 成长面板 | 今日状态、技能与知识点、学习热力图、掌握趋势、材料进度、计划节奏、证据来源 | 用卡片与图表解释成长，不使用孤立图标堆砌 |

### 3.2 左侧学习任务栏

左侧按“现在可做什么”组织，不提供工作区、项目、文件树或代码会话入口。

- **今日任务**：显示纸质材料名称、页码/题号、预计时长、当前状态和开始入口。
- **即将开始**：显示下一时间窗，可选择稍后、改期或暂停。
- **进行中与待反馈**：提示是否需要拍照、填写卡点或结束任务。
- **材料库**：记录已有练习册、试卷、教材和章节进度；材料建议仅作为可拒绝的顾问服务。
- **学习小工具**：学生可打开或生成与学习相关的小程序，例如番茄计时、背诵卡、公式卡、错题归档和复习清单。
- **周期回顾**：进入周/月回顾，而非展示开发日志或系统工具状态。

### 3.3 中间学习对话区

中间区域延续成熟的对话交互，但所有可影响计划、画像、授权和学习状态的输入都通过 Education Modal 或结构化卡片确认。

对话区可呈现：

- 学习目标澄清与支持性提问；
- 今日纸质任务说明；
- 任务开始、稍后、改期、暂停等确认；
- 作业照片/OCR 摘要与题目区域预览；
- 错因策略提示和分步引导；
- 动态计划建议及其证据依据；
- 语音输入的转写文本与学生确认入口。

对话区不呈现代码补丁、终端输出、工具调用日志、仓库路径、开发类 Skills 或与学习无关的系统状态。

#### 3.3.1 首次建档向导（已实现）

首次启动或无有效档案时，中间对话区显示“实用向导”而非自由对话，按 4 步结构化建立档案：

1. **基本信息**：称呼、年级；
2. **学科与重点**：学科多选、当前想突破的重点（可留空）；
3. **纸质材料登记**：材料名称、总页数、当前页码，可登记多份；
4. **学习节奏**：为每一项安排**灵活的开始时间与时长**——每份材料、重点突破、今日回顾各自对应自己的时间（`type="time"` 自由时刻 + 5–120 分钟时长），材料与时间一一对应，不使用固定时段预设。

学生确认后，由 L0/L1 规则（不调用大模型）确定性地生成初始任务：每份材料一个今日练习任务（页码区间，开始时间与时长取自该材料的逐项安排）、一个重点突破任务（有重点时）与一个今日回顾任务。档案、任务与证据时间戳保存在 PC 本地（`educationStore`），左侧任务栏与右侧成长面板（今日状态、学科证据、热力图、材料进度）均读取该数据层，不再使用静态演示数据；建档完成后中间区域进入真实对话。

#### 3.3.2 无材料时的联网推荐链路（已实现）

学生在建档向导第 3 步可以选择“我暂时没有纸质材料”。此时：

1. 材料登记变为可选，档案允许零材料完成建档；任务生成时优先生成「挑选纸质学习材料」引导任务（`material-shopping`），材料练习任务不再出现。
2. 建档确认后立即走**主链路对话**：系统自动向学习教练发送结构化请求，教练**联网搜索**（web search 工具），按学生的**年级、学科与当前重点（目标）**推荐 3 本真实可购买的**纸质**练习册或教材，逐本给出准确书名、出版社、适用年级、难度、推荐理由及与当前重点的关系。
3. 推荐仅是**可拒绝的顾问服务**：学生可以采纳某本并登记为材料（回到向导式登记）、拒绝、或要求换一批；不做任何强制加练。
4. 之后点击左侧「挑选纸质学习材料」任务会再次发起同一推荐对话，便于随时补充或更换材料。

### 3.4 右侧成长面板

右侧面板使用有层次的卡片与可读图表，避免只用图标替代信息。

1. **今日状态卡**：展示已完成任务、预计剩余时间、学习节奏和“下一步建议”。
2. **技能与知识点卡**：按学科展示掌握层级、最近证据、置信度和可纠正入口。
3. **学习热力图**：显示近期学习时间窗、完成与暂停情况，不将缺席自动解释为消极特质。
4. **掌握趋势图**：展示知识点的证据数量、趋势和覆盖度；完成次数不等同于掌握。
5. **材料进度卡**：将计划落到学生已有材料的章节、页码和订正状态。
6. **计划节奏卡**：显示本周计划与实际反馈差异，并以建议而非命令的形式给出调整选项。
7. **证据抽屉**：每张高影响卡片可查看来源、时间、学生自评、系统推断及其有效期；学生可以更正或删除授权范围内的数据。

### 3.5 视觉原则

- 使用温暖、克制的教育视觉语言：明确层级、柔和色块、可读数据图表和适度留白。
- 状态颜色必须有文字说明，不仅依赖红黄绿或装饰图标。
- 把“正在学习”“需要休息”“计划待确认”等状态设计成可理解、可操作的卡片。
- 不使用焦虑化倒计时、羞辱性排名、连续打卡压力或监控感强的摄像头状态展示。
- 图表默认展示聚合信息；需要查看明细时再展开，避免信息噪声。

## 4. Android 配套端设计

### 4.1 定位与设备范围

移动端仅规划 Android 应用，作为桌面教育版的配套学习陪伴与采集端。手机与 PC 通过明确授权的配对关系传输任务状态、压缩采集结果和必要事件；PC 是学习资料与证据的主要本地保存端。

### 4.2 主界面

主界面采用简洁、沉浸的对话式布局：

```text
顶部：当前学习任务 · 与 PC 的连接状态 · 隐私/采集状态
中部：圆形学习陪伴球
      - 前置摄像头开启时，仅本地显示低清实时预览
      - 语音输入或 AI 语音输出时，圆环随音量平滑波动
      - 无语音时显示任务进度与温和状态提示
底部：文本输入 · 按住说话/语音按钮 · 相机入口 · 前后摄像头切换 · 任务反馈
```

圆形区域不是身份识别界面，不保存或上传人脸模板。它只在用户主动开启前置摄像头时作为本地预览与语音反馈视觉载体。

### 4.3 语音交互

- 学生可语音说出卡点、完成情况和学习感受。
- 音频优先在端侧转写；发送前向学生展示文字并允许编辑或取消。
- 原始音频按最短必要期限保存或立即删除，默认不用于声纹识别或情绪声学分析。
- 语音球波动只反映当前音量，不推断情绪或人格状态。

### 4.4 前置摄像头：姿态辅助

姿态辅助为独立、默认关闭的功能。启用前需显著说明用途、采样方式、保存内容和关闭入口；未成年人场景需要监护人授权与学生知情。

#### 4.4.1 端侧处理链

```text
前置摄像头低清预览
  → 端侧姿态/在席类别估计
  → 形成短窗口时间序列
  → 本地聚合与阈值判断
  → 仅生成“非学习候选片段”摘要
  → 发送到 PC 事件账本
  → 必要时由规则或 LLM 判断是否给出温和建议
```

可记录的结构化类别包括：`focused_like`、`away_from_seat`、`looking_away_long`、`head_down_long`、`unknown`。这些类别只表示学习场景中的姿态或在席线索，不等同于注意力、态度、情绪、健康或学业能力。

#### 4.4.2 时序最小化规则

- 连续 `focused_like` 只在端侧累计，不上传逐帧信息，也不调用 LLM。
- 只有达到阈值的非学习候选片段才发送摘要，例如持续时长、开始结束时间、类别分布、置信度和任务上下文。
- `unknown`、低置信度、摄像头遮挡和网络异常均不用于判断学生状态。
- 一次候选片段最多触发一次轻量规则判断；是否进入 LLM 必须满足“持续异常、与任务反馈冲突或学生主动询问”之一。
- 输出只能是可忽略的提醒、建议休息、缩短任务或询问是否改期；禁止自动惩罚、告知家长用于纪律处理或更改长期评价。

### 4.5 后置摄像头：试卷与作业采集

后置摄像头进入“高清扫描模式”，用于学生主动拍摄试卷、作业、错题或材料目录。

#### 4.5.1 处理流程

```text
用户选择扫描试卷/作业
  → 后置摄像头高清预览与端侧帧质量评分
  → 按清晰度、抖动、反光、边缘完整度、透视偏差筛选关键帧
  → 选择少量最佳帧
  → 透视校正、裁切、压缩与 OCR
  → 学生预览题目区域与 OCR 文本，可重新拍摄或删除
  → 将关键帧、OCR 结果和元数据发送至 PC
  → PC 本地保存并生成学习证据
```

#### 4.5.2 图像与 OCR 原则

- “逐帧分析”只在手机端进行质量评分，不代表逐帧上传、逐帧调用云端模型或逐帧送入 LLM。
- 仅上传/传输经筛选的少量最佳关键帧；普通记录图片进行压缩，试卷题目区域保留足够 OCR 的清晰度。
- OCR 先在端侧或受控处理环境运行，输出文本必须允许学生确认；低置信识别不直接作为答案或掌握结论。
- 发送给 LLM 的是已裁切题目区域、确认后的 OCR 文本、题目来源和必要学习上下文，而不是整段视频或所有原图。
- PC 保存前提供去除姓名、校名、班级等无关个人信息的提醒；支持按单张证据删除。

## 5. PC—Android 数据协同

### 5.1 数据流

```text
Android：语音转写 / 非学习候选片段 / 最佳试卷关键帧与 OCR
  → 明确授权的加密传输或本地可信通道
  → PC 教育版事件账本与附件存储
  → L0/L1 更新任务与摘要
  → 必要时 L2 进行诊断或计划建议
  → PC 对话区与成长面板回显
  → 学生在任一端确认、忽略、更正或删除
```

### 5.2 保存与删除

- PC 是默认保存端：保存压缩附件、OCR 文本、结构化姿态摘要、任务事件和证据引用。
- 手机默认不长期保留原始视频；扫描过程结束后只保留用户确认要传输的关键帧，传输成功后按配置删除本地副本。
- 原始图像、OCR 结果、姿态摘要和计划推断分别设置保留期限与删除入口。
- 删除请求需要同步处理附件、OCR 文本、派生摘要和未完成分析任务，并保留法律允许范围内最小审计记录。

## 6. 模型调用与 Token 控制

### 6.1 分层执行

| 层级 | 执行内容 | 模型使用规则 |
|---|---|---|
| L0 | 授权检查、任务状态、相机帧评分、姿态窗口聚合、附件压缩、UI 回显 | 不调用大模型 |
| L1 | 模板话术、阈值判断、图表摘要、OCR 置信提示、轻量建议 | 本地规则或短上下文调用 |
| L2 | 错因解释、跨证据关联、计划重排、复杂 OCR 内容理解 | 异步、可取消、仅按需调用 |

### 6.2 上下文最小化

每次 L2 请求只携带与当前问题直接相关的内容：

1. 当前任务、学科和近期目标摘要；
2. 相关知识点、最近几条证据及其置信度；
3. 经聚合的姿态异常片段，而非全量时序；
4. 经过裁切和确认的 OCR 文本或题目区域；
5. 学生最近的自评与明确选择。

禁止向模型默认注入：全量数字孪生、完整聊天历史、全部图表原始数据、开发工具定义、代码工作区、持续视频流、逐帧姿态数据或无关小程序内容。

### 6.3 预算与去重

- 同一学生操作最多创建一个可合并的 L2 任务。
- OCR、姿态和反馈事件先在 L0/L1 合并，再决定是否需要 L2。
- 对重复的题目、重复的候选片段和相同计划建议使用摘要缓存与幂等键。
- 用户改期、暂停、关闭采集或取消上传时，取消尚未开始的深度分析。
- 小程序仅在学生显式打开或创建时加载其相关上下文，默认不进入学习对话的系统提示词。

## 7. 小程序与 Skills 策略

### 7.1 保留学习小程序

教育版保留小程序能力，但其可见模板和生成范围限定为学习辅助：

- 背诵卡、公式卡、知识点复习卡；
- 番茄计时器、学习计划看板、复盘记录器；
- 错题整理、试卷题目归档、材料清单；
- 学科知识点可视化和轻量自测工具。

小程序生成必须由学生或授权成人主动发起，并展示将使用的数据范围。小程序不应默认访问全部学习档案、摄像头内容或私密对话。

### 7.2 Skills 裁剪

教育版默认不提供代码开发、代码审查、调试、浏览器测试、CI、项目管理和终端运维类 Skills。可保留或新建的能力应围绕：学习规划、学科诊断、材料盘点、OCR 校验、错因策略、成长回顾、合规提示和学习小工具生成。

已实施的裁剪（2026-07-31）：删除代码审核 6 个、GitHub/CI 5 个、浏览器与测试 12 个、编码工具 3 个、诊断运维 5 个、文档招投标 3 个、novel-claude、股票评估实验技能共 36 个 skill 目录及 Skill 实验室数据目录；保留互联网调研、项目工具、多媒体设计三类共 13 个 skill（见 `codey/skills/categories.json`）。Skill 实验室、机器人管理、插件管理面板已从设置中移除；设置中保留 Skills 与本地知识库（知识/经验/数据库/小程序子页），左侧栏“我的材料库 / 学习小工具 / 学习能力”入口直达对应页面。

## 8. 验收与验证场景

1. **桌面端主闭环**：从左侧选择纸质任务，在中间确认开始，完成后上传照片或反馈，右侧知识点与计划节奏更新。
2. **视觉信息可读性**：右侧面板能在不查看原始数据的情况下说明今日状态、知识点证据、材料进度和下一步建议。
3. **Android 语音陪伴**：语音球随声音波动，转写可编辑；未确认的语音不写入学习档案。
4. **姿态最小化**：连续正常学习不产生 LLM 请求；非学习候选片段仅传输结构化摘要，提醒可忽略。
5. **试卷扫描**：后置摄像头从本地帧中选出少量清晰关键帧，完成校正、OCR、学生确认和 PC 本地保存。
6. **Token 控制**：L2 请求不包含开发工具、全量聊天、原始视频、全量姿态时序或无关小程序上下文。
7. **数据控制**：学生可以查看、删除试卷附件、OCR 文本、姿态摘要和授权范围内的派生学习证据。
