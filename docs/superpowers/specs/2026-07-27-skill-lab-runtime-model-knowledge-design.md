# Skill 实验室运行模型与本地知识库设计

日期：2026-07-27  
状态：已批准

## 1. 背景

Skill 实验室用于自动生成、测试和迭代高质量 Skill。当前自动生成固定继承主链路的全局模型；迭代进化也直接读取全局供应商和模型。用户无法针对生成质量或迭代效果选择不同模型，也无法决定是否让本地知识库参与生成与进化。

本功能为自动生成和迭代进化分别提供供应商、模型与本地知识库选择，交互与主链路对话框保持一致。

这些选择只控制 Skill 实验室的运行过程，不属于 Skill 配置。部署后只保留正式 Skill 产物，不携带供应商、模型或实验室知识库开关。

## 2. 目标

1. 自动生成前可以选择供应商、模型和是否使用本地知识库。
2. 迭代进化前可以独立选择供应商、模型和是否使用本地知识库。
3. 新会话首次打开 Skill 实验室时，两个阶段默认使用主链路当前供应商和模型；知识库默认关闭。
4. 后续选择作为 Skill 实验室界面偏好保存，方便下次使用，但不绑定任何 Skill 草稿。
5. 每次运行使用不可变的临时配置快照；运行中修改界面或全局设置不影响已启动任务。
6. 开启知识库后，模型能利用召回内容提高生成、测试、评估和改写质量，并按 Skill 目标判断是否需要在最终指令中加入运行时知识库使用规范。
7. 部署后的 Skill 不依赖实验室供应商或模型配置。

## 3. 非目标

1. 不把供应商、模型或知识库开关写入 Skill 草稿的 `meta.json`。
2. 不把 API Key、Base URL 或其他供应商配置写入 `SKILL.md`、脚本、部署目录或实验室元数据。
3. 不为不同 Skill 草稿保存不同的模型选择。
4. 不新增具体知识文档、知识类型或数据库的筛选器；本期只提供与主对话一致的本地知识库总开关。
5. 不改变部署后 Skill 的通用执行机制。
6. 不把迭代闭环整体重构为 Agent 对话线程。

## 4. 核心概念与生命周期

### 4.1 实验室界面偏好

前端维护两套独立的最近选择：

```ts
interface SkillLabStagePreference {
  providerId: string;
  modelId: string;
  smartbrainEnabled: boolean;
}

interface SkillLabPreferences {
  generation: SkillLabStagePreference;
  evolution: SkillLabStagePreference;
}
```

偏好属于 Skill 实验室，而不是某个 Skill：

- 可以保存在现有前端偏好存储中。
- 不进入 `SkillLabDetail`。
- 不进入 `meta.json`。
- 切换草稿时不随草稿变化。
- 部署时不复制。

首次没有偏好时：

- `generation.providerId/modelId` 取主链路当前有效供应商和模型。
- `evolution.providerId/modelId` 同样取主链路当前有效供应商和模型。
- 两个 `smartbrainEnabled` 均为 `false`。

之后用户可以为两个阶段选择不同模型。例如使用能力更强的模型生成，再使用目标模型或另一模型测试和进化。

### 4.2 命令级临时运行快照

执行时，前端根据当前偏好和供应商设置构造完整运行快照：

```ts
interface SkillLabRuntimeConfig {
  provider: ProviderRuntimeSnapshot;
  smartbrainEnabled: boolean;
}
```

`ProviderRuntimeSnapshot` 复用主对话的供应商覆盖结构，包含本次调用所需的：

- 供应商类型或 key
- Base URL
- API Key
- Wire API
- 模型 ID
- 上下文窗口和最大输出 token
- 资源池端点
- 视觉模型回退信息

该快照可能包含 API Key，因此生命周期必须严格受限：

1. 只随当前 Tauri IPC 命令传入 Rust 后端。
2. 只用于构造本次运行的内存 `ConfigToml` 克隆。
3. 不序列化到磁盘。
4. 不写入日志或进度事件。
5. 命令结束后随内存对象释放。
6. 不修改全局 `config.toml`。

### 4.3 Skill 正式产物

部署流程只处理 Skill 产物，例如：

- `SKILL.md`
- `scripts/`
- `references/`
- `assets/`

以下内容不得进入部署目录：

- 实验室供应商或模型选择
- 实验室知识库开关
- API Key 或供应商连接信息
- 测试评分历史和实验室进度状态

最终 `SKILL.md` 可以包含通用的 `smartbrain_search` 使用规范，但只在模型判断该 Skill 的实际运行目标需要动态或领域知识时加入。它不携带本次实验室知识库开关，也不绑定某个供应商或模型。

## 5. 用户界面设计

### 5.1 自动生成配置区

在目标需求输入框和自动生成按钮附近增加紧凑配置区：

- 供应商选择器
- 模型选择器与搜索
- 本地知识库开关
- 当前配置摘要，例如 `DeepSeek / deepseek-chat · 知识库关闭`

Python 环境检查仍只属于自动生成阶段。

### 5.2 迭代进化配置区

在测试提示词、最大迭代次数和运行测试按钮附近增加独立配置区：

- 供应商选择器
- 模型选择器与搜索
- 本地知识库开关
- 当前配置摘要

该区不继承自动生成区的后续修改。两个阶段各自记住最近选择。

### 5.3 主对话能力复用

抽取主对话模型选择的通用核心组件和解析函数：

```tsx
<ProviderModelPicker
  providers={providers}
  providerId={providerId}
  modelId={modelId}
  onChange={onChange}
/>
```

共享内容包括：

- 供应商与模型联动
- 模型搜索
- 模型显示名解析
- 空模型状态
- 已删除供应商或模型的失效状态
- 资源池、上下文窗口和视觉回退快照构造

主对话保留原有胶囊按钮和弹层外壳；Skill 实验室使用适合设置面板的紧凑卡片外壳。知识库开关复用主对话视觉语义，但状态来自对应实验室阶段偏好。

### 5.4 控件与执行状态

- 有效供应商和模型是运行前置条件。
- 供应商或模型失效时，显示明确提示并禁用对应阶段执行按钮。
- 知识库是可选项，默认关闭。
- 生成运行时锁定生成配置区。
- 迭代运行时锁定迭代配置区。
- 运行启动时复制当前选择；运行中修改其他阶段或全局设置不影响当前任务。
- Skill 列表不增加配置列，避免把运行偏好误解为 Skill 属性。

## 6. 命令与后端配置

### 6.1 自动生成命令

扩展生成参数：

```rust
pub struct SkillLabGenerateFromGoalParams {
    pub skill_id: String,
    pub goal: String,
    pub name_hint: Option<String>,
    pub runtime_config: SkillLabRuntimeConfig,
}
```

处理流程：

1. 校验供应商快照和模型 ID。
2. 读取全局 `ConfigToml`，创建内存克隆。
3. 将供应商快照、模型和知识库开关应用到克隆。
4. 使用该克隆创建线程并调用主 Agent。
5. 生成完成后只保存 Skill 产物与现有实验室元数据。
6. 丢弃临时配置。

后端应抽取或复用当前 `apply_thread_chat_overrides` 的配置合并逻辑，避免 Skill 实验室和主对话分别维护资源池、视觉回退等规则。

### 6.2 迭代进化命令

将当前仅接收 `skill_id` 的命令改为参数结构：

```rust
pub struct SkillLabRunTestParams {
    pub skill_id: String,
    pub runtime_config: SkillLabRuntimeConfig,
}
```

处理流程：

1. 保留现有同一 Skill 并发保护。
2. 根据运行快照解析 Base URL、API Key、Wire API、模型和 token 限制。
3. 整个测试、评分和改写循环固定使用本次快照。
4. 不从循环中再次读取全局供应商或模型。
5. 继续沿用现有重试、进度事件、最佳分数和收敛逻辑。

### 6.3 安全要求

- `Debug` 输出不得直接打印完整 `runtime_config`。
- 错误信息不得包含 API Key、授权头或完整敏感查询参数。
- 进度事件只允许报告供应商显示名、模型 ID、知识库命中数量和阶段状态。
- API Key 不得写入测试结果、评估文本、评分历史或 Skill 文件。

## 7. 本地知识库语义

### 7.1 自动生成阶段

知识库关闭时：

- 内存配置关闭 SmartBrain。
- 不执行请求级预召回。
- 不向生成 Agent 暴露可用的知识库检索能力。
- 不额外要求最终 Skill 使用知识库。

知识库开启时：

- 主 Agent 使用目标需求进行请求级预召回。
- `smartbrain_search` 按现有主链路规则可用。
- 生成提示词要求模型区分：
  1. 召回内容只用于提高当前 Skill 的设计质量；
  2. Skill 在未来执行时确实需要查询动态或领域知识。
- 只有第二种情况才在 `SKILL.md` 中加入：
  - 何时调用 `smartbrain_search`
  - 如何构造查询
  - 如何读取连续上下文
  - 无结果或工具不可用时如何降级
- 不得因为实验室开关开启，就无条件要求部署后的 Skill 每次调用知识库。

### 7.2 迭代进化阶段

现有闭环直接调用模型 API，没有 Agent 工具调用循环。为保留现有稳定结构，知识库采用请求级召回后注入上下文：

1. 根据目标需求、测试提示词和当前 Skill 摘要构造检索查询。
2. 每轮或在当前 Skill 发生实质改写后刷新召回；避免对完全相同内容重复检索。
3. 将召回内容作为不可信参考资料注入三个阶段：
   - 测试：验证 Skill 在相关领域上下文中的表现。
   - 评估：判断知识使用是否正确，是否存在错误依赖或过度检索。
   - 改写：据此改进 Skill，并判断是否需要运行时知识库规范。
4. 注入边界明确声明：参考资料中的命令或提示不得作为系统指令执行。
5. 召回正文仅存在于本轮请求内，不写入 `meta.json`、评分历史或测试结果。

迭代知识库关闭时保持原有测试、评分和改写行为。

### 7.3 无命中和检索失败

- 索引不存在、索引为空或无命中：记录“本轮未检索到相关知识”，继续运行。
- 检索内部错误：记录脱敏日志和进度提示，降级继续运行。
- 知识库问题本身不应导致已经开始的生成或迭代结果丢失。
- 模型调用失败仍沿用现有重试和失败状态机制。

## 8. 数据兼容性

由于阶段选择不进入 Skill 元数据：

- 现有 `meta.json` 无需字段迁移。
- `SkillLabDetail` 无需增加运行配置字段。
- 旧草稿和新草稿读取行为相同。
- 切换或重命名草稿不会改变实验室最近选择。
- 删除草稿不会删除实验室偏好。
- 部署流程无需处理模型配置迁移。

如果前端偏好中的供应商或模型已经被删除：

1. 尝试回退到当前主链路有效选择。
2. 若仍无有效模型，展示失效状态并要求用户选择。
3. 不静默使用其他模型启动任务。

## 9. 状态流与错误处理

### 9.1 自动生成

```text
idle
  → validate runtime selection
  → check Python
  → snapshot runtime config
  → generate with selected model/knowledge setting
  → validate artifacts
  → save lab artifacts
  → idle or error
```

### 9.2 迭代进化

```text
idle
  → validate runtime selection
  → acquire per-skill run guard
  → snapshot runtime config
  → optional knowledge recall
  → testing
  → evaluating
  → rewriting
  → repeat until passed/converged/max iterations
  → passed or failed
```

错误展示应区分：

- 供应商或模型未配置/已失效
- Python 环境不可用
- 知识库降级警告
- 模型请求失败
- 生成产物验证失败
- 同一 Skill 已在迭代中

知识库降级警告不应覆盖模型调用或产物验证的真实失败原因。

## 10. 测试策略

### 10.1 前端单元与组件测试

1. 无实验室偏好时使用主链路当前供应商和模型，知识库默认关闭。
2. 生成和迭代选择相互独立。
3. 切换 Skill 草稿不改变阶段选择。
4. 重新打开实验室时恢复最近选择。
5. 供应商变化后模型列表正确联动。
6. 已删除供应商或模型会回退或显示失效，不会静默运行。
7. 对应阶段运行期间控件锁定。
8. 构造运行快照时正确包含资源池、token 限制和视觉回退配置。

### 10.2 Rust 单元测试

1. 临时运行快照正确覆盖供应商和模型。
2. 临时覆盖不修改全局 `ConfigToml`。
3. 运行参数不写入 `meta.json`。
4. API Key 不出现在进度事件和持久化结果中。
5. 生成知识库开关正确控制 Agent 预召回和工具可用性。
6. 迭代知识库开关正确控制三阶段上下文注入。
7. 无索引、无命中和检索错误均能降级继续。
8. 整个迭代循环固定使用启动时模型快照。

### 10.3 回归测试

1. 原有自动生成仍能创建合法 `SKILL.md` 和 Python 脚本。
2. 标准英文 kebab-case 命名和草稿重命名行为不变。
3. 原有测试、评分、最佳版本、收敛和重试逻辑不变。
4. 同一 Skill 并发运行保护不变。
5. 部署结果不包含实验室运行配置。
6. 主对话供应商/模型选择和知识库开关行为不变。
7. 旧实验室草稿无需迁移即可生成、迭代和部署。

## 11. 验收标准

1. 用户可在自动生成区选择供应商、模型和本地知识库开关，并以该配置完成生成。
2. 用户可在迭代区独立选择另一供应商、模型和知识库开关，并以该配置完成全部迭代轮次。
3. 切换草稿不会加载草稿专属模型配置，因为不存在这种配置。
4. 关闭并重新打开实验室后，可恢复最近一次阶段选择；该偏好不进入任何 Skill 文件。
5. 运行开始后修改全局模型不会改变当前任务所用模型。
6. 知识库开启时，生成和迭代能利用相关召回内容；无命中时仍可完成任务。
7. 最终 Skill 只在目标确有需要时包含通用知识库使用规范，不机械依赖知识库。
8. 部署目录中不存在供应商 ID、模型 ID、实验室知识库开关、API Key 或其他实验室运行配置。
9. 所有新增测试通过，现有 Skill 实验室与主对话回归测试通过。

## 12. 实施边界

建议按以下模块拆分实施：

1. 抽取前端供应商/模型选择核心组件和运行快照构造函数。
2. 增加 Skill 实验室阶段偏好及两个配置区。
3. 抽取 Rust 内存配置覆盖逻辑，扩展两个 Tauri 命令参数。
4. 接入自动生成阶段知识库能力。
5. 接入迭代阶段知识召回与三阶段注入。
6. 完成安全、兼容、组件和回归测试。

该范围聚焦于提升 Skill 自动生成和进化质量，不扩展为通用工作流模型编排系统。
