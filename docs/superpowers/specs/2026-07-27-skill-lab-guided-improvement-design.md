# Skill 实验室引导式一键改进设计

日期：2026-07-27  
状态：已批准

## 1. 背景

Skill 实验室现有列表可以打开草稿详情，详情保存最近一次测试结果和 AI 评估，并提供“运行测试”入口。后端已经具备“测试 → 评估 → 改写 → 重复”的自动进化闭环，但用户无法从列表直观看出哪些 Skill 需要继续改进，也无法在启动闭环前确认、编辑或补充本次改进目标。

本功能为评估未通过的 Skill 增加“需要改进”标识，并在详情中把最近 AI 评估转成可编辑的本次改进要求。用户确认后点击“一键改进”，复用现有闭环完成有目标的自动迭代更新。

## 2. 目标

1. 列表明确标记评估未通过且存在最近评估意见的 Skill。
2. 点击该 Skill 后，在详情中展示自动带入、可编辑的改进要求。
3. 用户点击“一键改进”后，将该要求作为本次运行的固定目标传入现有自动迭代闭环。
4. 改进目标参与测试、评估和改写，使每轮都能验证是否满足目标，而不是仅执行一次无验证改写。
5. 运行完成后刷新详情和列表；通过后自动移除“需要改进”标识，未通过则展示新的评估并允许再次改进。
6. 改进要求属于请求级运行数据，不写入 Skill 元数据或部署产物。

## 3. 非目标

1. 不新增独立的一次性改写引擎。
2. 不在点击列表项时立即调用模型。
3. 不修改草稿的正式目标 `goal` 或测试提示词 `testPrompt` 来承载改进要求。
4. 不为已通过、未测试或没有评估意见的 Skill 显示“需要改进”。
5. 不保存历史改进要求列表。
6. 不改变现有供应商、模型、本地知识库和资源池运行快照语义。
7. 不改变部署门槛、评分阈值或并发运行保护。

## 4. 判定规则

后端列表摘要增加只读计算字段：

```rust
pub struct SkillLabSummary {
    pub id: String,
    pub name: String,
    pub status: String,
    pub iteration_count: u32,
    pub needs_improvement: bool,
}
```

`needs_improvement` 仅在以下条件同时成立时为 `true`：

1. 规范化状态为 `failed`；
2. `last_evaluation` 存在；
3. `last_evaluation.trim()` 非空。

该字段由已有 `meta.json` 内容计算，不新增持久化字段，因此旧草稿无需迁移。前端不自行复制判定规则。

## 5. 交互设计

### 5.1 列表

- `needsImprovement=true` 的行展示“需要改进”状态徽标。
- 行点击行为仍为打开详情，不自动启动模型任务。
- 正在运行、已通过和已部署状态继续使用现有状态展示；“需要改进”是失败状态的明确用户语义。

### 5.2 详情改进区

仅当当前详情满足“状态为 failed 且最近评估非空”时显示改进区。

改进区包含：

1. 标题“自动改进”；
2. 说明文字，明确内容来自最近 AI 评估且可修改；
3. 多行文本框；
4. “恢复最近评估”按钮；
5. “一键改进”按钮。

打开或切换草稿时，文本框初始化为最近 AI 评估的可读改进内容。若评估为合法 JSON，优先提取：

- `criticalIssues`，渲染为“关键问题”列表；
- `improveHints`，渲染为“改进建议”列表。

同时兼容 snake_case 字段 `critical_issues` 和 `improve_hints`。如果无法解析 JSON、两个数组均为空或评估本身是自然语言，则回退使用去除首尾空白后的原始评估文本。

用户编辑内容只存在于当前详情会话。切换草稿时按对应草稿最近评估重新初始化，不跨 Skill 复用。

### 5.3 启动条件

“一键改进”仅在以下条件成立时可用：

- 当前 Skill 需要改进；
- 改进要求非空；
- Skill 内容和测试提示词非空；
- 迭代运行配置有效；
- 当前 Skill 没有正在运行的迭代任务。

点击后先执行现有保存逻辑，再捕获迭代阶段运行配置快照并启动命令。按钮运行态、进度、结果弹窗和错误展示复用现有迭代状态。

普通“运行测试”仍可用于任何具备内容和测试提示词的草稿，其 `improvementRequest` 为空。

## 6. 前端数据流

新增纯函数模块负责评估解析和判定，避免把 JSON 兼容逻辑堆入面板组件：

```ts
export function formatSkillLabImprovementRequest(
  lastEvaluation: string | null | undefined,
): string;

export function detailNeedsImprovement(detail: {
  status: string;
  lastEvaluation: string | null;
} | null): boolean;
```

`SkillLabPanel` 增加 `improvementRequest` 状态：

1. 读取详情成功后，根据 `lastEvaluation` 初始化；
2. 创建新草稿时清空；
3. 点击“恢复最近评估”时重新格式化；
4. 普通运行测试调用统一运行函数并传 `null`；
5. 一键改进调用统一运行函数并传当前文本快照。

统一运行函数在发起 IPC 前对改进要求执行 `trim()`，确保任务运行期间不受后续界面编辑影响。

## 7. IPC 与后端闭环

扩展运行参数：

```rust
#[derive(Debug, Deserialize)]
#[serde(rename_all = "camelCase")]
pub struct SkillLabRunTestParams {
    pub skill_id: String,
    pub runtime_config: SkillLabRuntimeConfig,
    #[serde(default)]
    pub improvement_request: Option<String>,
}
```

后端在命令开始时规范化：

- `None` 或空白字符串转为 `None`；
- 非空内容进行长度限制；
- 超出上限时返回明确错误，不静默截断，避免用户要求被悄然改变；
- 内容仅保存在当前函数内存中。

建议最大长度为 12,000 个 Unicode 字符，足以容纳评估意见并防止意外超长上下文。

### 7.1 测试阶段

存在改进要求时，将其作为不可信的用户目标附加到测试用户消息中，要求模型在遵守 Skill 的同时覆盖这些目标。改进要求不得覆盖 Skill 指令或本地知识库安全边界。

### 7.2 评估阶段

将固定改进要求加入评估输入，要求评估器检查：

- 新输出是否解决指定问题；
- 是否引入回归；
- 尚未满足的目标继续进入 `criticalIssues` 或 `improveHints`。

JSON 输出结构保持不变，避免迁移评分解析和历史记录。

### 7.3 改写阶段

将固定改进要求作为“本次改进目标”加入改写输入，其优先级高于模型本轮给出的普通改进建议，但不得覆盖系统安全要求或改变 Skill 的原始用途。

现有每轮关键问题澄清仍保留。用户在运行中补充的澄清内容与固定改进目标同时注入：

- 固定改进目标：整次运行不变；
- 本轮澄清：只补充当前轮改写。

### 7.4 无改进要求

普通“运行测试”传入 `None` 时，测试、评估和改写消息必须保持现有形状，确保回归兼容。

## 8. 持久化与安全

以下内容不得写入 `SkillLabMeta`、`meta.json`、评分历史、测试结果、`SKILL.md`、脚本或部署目录：

- `improvementRequest`；
- 改进区编辑中的临时文本；
- 供应商运行快照和密钥。

进度日志可以说明“已应用本次改进目标”，但不得输出完整改进文本，以免评估内容包含敏感信息。

改进要求按用户数据处理，不作为系统指令；注入提示中明确它不能覆盖系统、安全和工具边界。

## 9. 错误和状态处理

- 改进要求为空：前端禁用按钮；后端仍校验并返回明确错误，防止绕过。
- 改进要求过长：保留编辑内容，展示后端错误，不启动闭环。
- 保存失败：不启动迭代。
- 模型或知识库失败：沿用现有模型失败和知识库降级逻辑。
- 用户停止澄清：保留当前最佳版本，与现有行为一致。
- 运行完成：重新读取详情和列表，并用最新评估重新初始化改进区。

## 10. 测试策略

### 10.1 TypeScript 单元测试

1. 合法 camelCase JSON 提取关键问题和改进建议。
2. snake_case JSON 字段兼容。
3. 代码块包裹的 JSON 能解析。
4. 无法解析或数组为空时回退原始文本。
5. 空评估返回空字符串。
6. 仅 `failed` 且评估非空时判定需要改进。

### 10.2 Rust 单元测试

1. 列表计算字段只对失败且有评估的草稿为真。
2. 改进要求空白规范化为 `None`。
3. 超长改进要求返回错误。
4. 测试、评估和改写消息均注入固定目标。
5. 注入内容包含不可信输入边界。
6. 无改进要求时消息保持原结构。
7. `SkillLabMeta` 序列化不包含 `improvementRequest`。

### 10.3 回归测试

1. 普通运行测试行为不变。
2. 一键改进使用当前选择的迭代供应商、模型、资源池和知识库快照。
3. 切换列表项不会自动调用模型。
4. 通过后列表不再显示“需要改进”。
5. 未通过后展示最新评估并可再次改进。
6. 部署产物不包含改进要求或运行配置。

## 11. 验收标准

1. 评估未通过且有评估意见的 Skill 在列表中显示“需要改进”。
2. 点击列表项只打开详情，不自动产生费用。
3. 详情自动带入结构化、可编辑的改进要求。
4. 点击“一键改进”后，现有测试—评估—改写闭环按该固定目标运行。
5. 普通“运行测试”不受影响。
6. 运行结束后列表和详情反映最新状态；通过后标识消失。
7. 改进要求不写入任何 Skill 元数据或部署产物。
8. 新增测试、前端构建和 Rust 编译检查通过。
