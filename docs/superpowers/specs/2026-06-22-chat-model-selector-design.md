# 对话模型双下拉选择器设计

## 目标

将对话输入区现有的“全部供应商和模型平铺列表”改为两段联动选择：先选择供应商，再通过支持文字输入筛选的模型下拉框选择模型。同时保证新建对话默认继承设置中已启动的供应商，而不是被旧版模型状态或上一对话覆盖。

## 状态规则

1. 新建对话必须清除上一对话的 `overrideProviderId` 和 `overrideModelId`。
2. 未设置对话级覆盖时，有效供应商严格使用全局 `activeProviderId`。
3. 有效模型按以下顺序解析：
   - 当前对话覆盖模型，但必须属于有效供应商；
   - 全局 `currentModel`，但必须属于有效供应商；
   - 旧版 `activeModelId` 对应模型，但必须属于有效供应商；
   - 有效供应商模型列表第一项。
4. 旧版 `activeModelId` 不得把已启动的 Z-API 覆盖成 Grok。
5. 在对话中选择供应商或模型只修改当前对话覆盖，不修改设置中的全局启动供应商。

## 交互设计

- 模型菜单显示在聊天输入框上方。
- 第一项为供应商原生下拉框，默认选中当前有效供应商。
- 第二项为可搜索模型组合框：输入内容后按模型名称和模型 ID 进行不区分大小写的包含匹配。
- 切换供应商后，模型搜索词清空，模型候选列表切换到该供应商，并默认选择该供应商的全局模型或第一项。
- 选择模型后关闭模型候选列表和整个模型菜单。
- 保留“使用全局默认”操作，用于清除当前对话覆盖。
- 无匹配结果时显示明确空状态。

## 防遮挡与响应式

- 模型菜单使用受限宽度并锚定在输入框上方，不覆盖输入框和发送按钮。
- 两个选择控件在中等及以上宽度并排，小窗口自动纵向排列。
- 模型候选列表使用最大高度和内部滚动，不随模型数量无限增高。
- 菜单整体最大高度受视口限制并内部滚动。

## 测试

- 单元测试覆盖有效模型解析，特别是“Z-API 已启动但旧版 activeModel 指向 Grok”的场景。
- 单元测试覆盖模型名称/ID、不区分大小写、空查询和无结果筛选。
- Store 回归测试继续覆盖启用供应商同步模型和新建对话清除覆盖。
- 执行全部前端测试与生产构建。
