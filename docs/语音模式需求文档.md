# 语音模式（Voice Mode）需求文档

> 版本：v0.2（已按需求方意见修订）
> 日期：2026-07-18
> 状态：**已确认，可进入实施**
> 关联模块：对话主链路（FR-003）、配置管理（FR-005）、设置界面

---

## 1. 背景与目标

CN-Codex 当前仅支持文字输入输出。本需求为应用增加**本地语音模式**：

1. 语音输入：用户说话 → 本地 ASR 转文字；
2. 意图识别：由默认供应商 LLM 判断用户意图，分为两类：
   - **闲聊（chat）**：纯聊天，走"个性设置"中定义的性格与语言风格回复用户；
   - **解决问题（solve）**：将用户口述的问题总结后注入现有对话主链路处理；
3. 语音输出：LLM 回复通过本地 TTS 播放；
4. **全部模型本地运行、CPU 推理、体积小、速度快**；
5. 启动时自动检查模型是否已下载，缺失则从 **ModelScope（魔搭社区）** 下载。

### 1.1 核心约束

| 约束 | 说明 |
|------|------|
| CPU 推理 | 不依赖 GPU，仅用 CPU（ONNX int8 量化） |
| 速度优先 | ASR/TTS 实时率 RTF ≤ 0.3（参考机型 4 核 CPU、4 线程） |
| 闲聊不出现在主界面 | 闲聊分支不在对话界面显示任何文字 |
| 个性设置与主链路无关 | 性格/风格仅作用于闲聊回复，不污染主链路 system prompt |
| 自动下载 | 启动时自动检查并后台自动下载缺失模型，无需用户手动触发 |
| 模型来源 | ModelScope 优先（国内速度快），GitHub Release 作为备用源 |

## 2. 模型选型（已核实 ModelScope 资源）

### 2.1 ASR（语音转文字）：Qwen3-ASR-0.6B（sherpa-onnx int8 版）

| 项 | 内容 |
|------|------|
| 模型 | Qwen3-ASR-0.6B int8（sherpa-onnx 格式） |
| 体积 | 约 0.9 GB（tar.bz2 打包） |
| 引擎 | sherpa-onnx（官方提供 Rust API，可直接嵌入 Tauri Rust 后端） |
| 语言 | 中文、英文、粤语等 29 种语言 + 20 种中文方言 |
| CPU 性能 | 官方基准：2 线程 RTF ≈ 0.128（28.9 秒音频约 3.7 秒完成） |
| ModelScope 主源 | `zhaochaoqun/sherpa-onnx-asr-models` → `Qwen3-ASR-0.6B.tar.bz2` |
| 备用源 | GitHub `k2-fsa/sherpa-onnx` Release（`sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25`） |

> 说明：Qwen3-ASR 官方开源最小规格即 0.6B；1.7B 版本体积约 2.5 GB、CPU 速度明显下降，不采用。如未来出现更小规格可替换。

### 2.2 TTS（文字转语音）：Kokoro-82M int8 中英双语版

| 项 | 内容 |
|------|------|
| 模型 | Kokoro-82M v1.1 int8 多语言版（sherpa-onnx 格式） |
| 体积 | 约 175 MB（model.int8.onnx 114 MB + voices.bin 54 MB + espeak-ng-data/词典/FST） |
| 语言 | 中文 + 英文（混合文本可合成） |
| 音色 | 内置多音色（voices.bin），默认选一个中文自然女声 |
| CPU 性能 | int8 量化后 RTF ≈ 0.1~0.2，速度满足实时对话 |
| ModelScope 主源 | `gomodels/sherpa` → `kokoro-int8-multi-lang-v1_1/` |
| 备用源 | GitHub `k2-fsa/sherpa-onnx` Release 同名目录 |
| 备选方案 | `matcha_tts_zh_en_20251010`（约 130 MB，中文效果稍弱），如 Kokoro 中文效果不达标可切换 |

### 2.3 VAD（语音活动检测，可选但建议）

| 项 | 内容 |
|------|------|
| 模型 | silero-vad（sherpa-onnx 格式） |
| 体积 | 约 2.3 MB |
| 用途 | 自动检测"开始说话/停止说话"，实现免按键的连续语音对话 |
| ModelScope 主源 | `gomodels/sherpa` → `vad/silero_vad.onnx` |

### 2.4 模型存储位置

```

├── asr-qwen3-0.6b-int8/     # ASR 模型（解包后）
├── tts-kokoro-int8/         # TTS 模型
├── vad/                     # silero-vad
└── manifest.json            # 模型版本、来源、校验信息
```

## 3. 模型下载与就绪管理

### 3.1 启动时自动检查与自动下载

- 应用启动时（后台线程，不阻塞 UI）**自动**检查 `voice-models/manifest.json` 与各模型目录完整性；
- 完整 → 状态置为"就绪"，不产生任何 UI 干扰；
- 缺失/损坏 → **自动进入后台下载**（默认行为，无需用户手动触发），同时右下角出现下载列表（见 3.3）；
- 下载期间应用其余功能全部可用；语音功能在对应模型就绪前不可用（见 3.4）。

### 3.2 下载流程

- 下载源：优先 ModelScope，失败自动切换 GitHub Release 备用源；
- 支持断点续传；下载前/后做文件大小校验（后续可加哈希）；
- tar.bz2 解包到对应目录，写入/更新 `manifest.json`；
- 下载进度通过 Tauri 事件推送给前端，设置页与语音按钮同步显示；
- 下载可暂停/取消；下载失败可在下载列表与提示浮层中一键重试；下载期间应用其余功能不受影响；
- 设置页保留"语音模型"卡片：显示 ASR/TTS/VAD 三个模型的状态、体积、来源，支持手动重新下载/删除。

### 3.3 右下角下载列表（全局小组件）

- 位置：主窗口右下角固定浮层，默认展开；宽约 260px，紧凑单行条目；
- 每个正在下载的模型一行：`模型名 + 细进度条 + 百分比 + 速度`；
- 列表整体可折叠为一个小图标（下载中显示旋转动效），不遮挡聊天输入区；
- 全部下载完成后列表自动消失；失败条目保留并显示"重试"按钮；
- 设计目标为"轻提醒"：够小、够简洁，用户瞥一眼即知正在下载与进度。

### 3.4 未就绪使用提示

- 当用户点击语音按钮（需要 ASR）或触发任何需要 TTS 的动作，而对应模型尚未就绪时：
  - 弹出轻量提示（toast/浮层）："语音识别 / 语音合成尚未准备完毕，模型下载完成后才能使用此功能"；
  - **右下角出现"重试下载"按钮**，点击立即重试缺失模型的下载；
  - 提示不阻塞其他界面操作，数秒后自动淡出，下载进度仍由右下角下载列表承载。

## 4. 语音模式交互流程

### 4.1 总体流程

```
用户说话
   │  （VAD 自动检测说话起止，或按住说话）
   ▼
录音（16kHz 单声道 PCM）
   ▼
本地 ASR（Qwen3-ASR-0.6B int8, CPU）→ 转写文本
   ▼
默认供应商 LLM —— 意图识别（一次调用，JSON 输出）
   ├─ {"intent":"chat",  "reply":"……"}               → 闲聊分支
   └─ {"intent":"solve","summary":"……","ack":"……"}  → 解决问题分支
        ▼
   弹出确认卡片（展示总结文本 summary + 确认发送 / 取消按钮）
        ▼ 用户确认
   summary 注入对话主链路  ‖  同时 TTS 播放 ack（LLM 生成的开始任务话术）
```

### 4.2 闲聊分支（chat）

- 使用**个性设置**（见第 6 节）拼接闲聊专用 system prompt；
- 携带**闲聊专用上下文**（仅闲聊轮次，最近 N 轮，默认 10，不持久化、可一键清空）；
- LLM 回复 `reply` → 本地 TTS 播放；
- **对话界面不显示任何文字**（包括用户说的内容和闲聊回复），仅允许显示非文字状态提示（麦克风/声波动画、"正在聆听/正在回答"）；
- 闲聊内容不写入会话历史、不进入主链路、不落盘。

### 4.3 解决问题分支（solve）

- LLM 意图识别时同时输出两个内容：
  - `summary`：对用户口述问题的精炼总结（用于注入主链路）；
  - `ack`：LLM 生成的"开始执行任务"确认话术（用于语音播报）；
- `summary` **先展示给用户确认**：语音模式浮层弹出确认卡片，显示总结文本与「确认发送 / 取消」按钮；卡片打开期间用户也可直接语音回答，由 LLM 判定"确认 / 取消"意图（复用现有 LLM 意图识别管线，不写死关键词）；
- 用户确认后：`summary` 作为用户消息发送到现有对话主链路（`turn/start`），出现在对话界面中；**同时** TTS 开始播放 `ack`；
- **主链路回复不朗读**：solve 的回复仅以文字形式显示在对话界面，TTS 不播报主链路回复；
- 语音被判为"取消"时关闭确认卡片、丢弃本次总结，回到聆听状态。

### 4.4 播放与打断

- TTS 播放期间用户再次说话（VAD 检测到）或点击停止 → 立即停止播放并进入聆听状态（可打断）；
- 播放队列：一次回复切句合成、顺序播放，降低首包延迟；
- 界面提供明确的语音模式开关（麦克风按钮），开启后进入"边听边聊"状态，关闭后恢复纯文字模式。

## 5. 意图识别设计

- **纯 LLM 判定**：意图识别完全由 LLM 完成，**禁止**使用正则、关键词表等硬编码规则；判定标准写在 system prompt 中由模型理解执行；
- **执行者**：当前默认供应商的默认 LLM（与主链路相同模型，不引入第二个模型）；
- **时机**：每次语音转写完成后调用一次，**同时完成意图分类与输出生成**，避免两次 LLM 调用：
  - `chat` → 输出 `reply`（结合个性设置的闲聊回复）；
  - `solve` → 输出 `summary`（问题总结）+ `ack`（LLM 生成的开始任务话术）；
- **无硬编码表达**：所有面向用户的语音文本（闲聊回复、ack 确认话术）均由 LLM 生成，代码中不得出现写死的播报模板（如"好的，马上开始"）；
- **输出格式**：严格 JSON，解析失败时重试一次；再失败则默认按 solve 处理（summary 退化为 ASR 原文本，仍走确认卡片），保证主任务不丢；
- **判定标准**（写入 system prompt，由 LLM 自行理解，可附少量 few-shot 示例，示例不构成运行时规则）：
  - 涉及编程、代码、项目、文件、命令、技术问题、任务请求 → `solve`；
  - 问候、寒暄、情绪表达、与项目无关的日常问答 → `chat`。

## 6. 设置模块：新增"个性设置"

位置：设置 → 新增「个性设置」页签。

| 配置项 | 说明 | 默认值 |
|------|------|------|
| 性格预设 | 友好随和 / 专业严谨 / 幽默风趣 / 简洁直接 / 自定义 | 友好随和 |
| 语言风格 | 口语化 / 正式 / 活泼网络化 / 简短 | 口语化 |
| 自定义提示词 | 用户附加的性格描述（自由文本） | 空 |
| 闲聊上下文轮数 | 1~20 | 10 |
| 清空闲聊上下文 | 按钮，立即生效 | — |
| TTS 音色 | voices.bin 内音色列表 | 默认中文女声 |
| TTS 语速 | 0.8x ~ 1.5x | 1.0x |
| VAD 自动断句 | 开启后免按键说话；关闭则按住说话 | 开 |

**关键约束**：个性设置只拼进闲聊分支的 system prompt，绝不修改主链路（solve 分支）的任何提示词与行为。

## 7. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | ASR：短句（<3s 音频）转写 ≤ 2s；TTS：整句合成 RTF ≤ 0.3；模型加载一次常驻内存，不重复加载 |
| 资源 | 模型常驻内存约 1 GB 内；空闲时 CPU 占用 ≈ 0（仅 VAD 轻量推理） |
| 隐私 | 语音全部本地处理；录音缓存用后即删，不落盘、不上传 |
| 离线 | 模型就绪后，ASR/TTS/VAD 全程离线可用；LLM 意图识别依赖已配置的供应商网络 |
| 可靠性 | 下载失败可重试、可切换备用源；ASR/TTS 引擎崩溃不影响主应用（子线程隔离 + 自动重载一次） |
| 兼容 | Windows x86_64 优先（当前平台）；接口设计预留 macOS/Linux |
| i18n | 所有新增 UI 文案走现有 fluent/react-intl 双语机制 |

## 8. 技术实现要点（实施参考）

| 层 | 方案 |
|------|------|
| 推理引擎 | Rust 侧集成 `sherpa-onnx`（官方 Rust API / 或 FFI 封装），ASR/TTS/VAD 同一引擎 |
| 下载 | Rust `reqwest` 流式下载 + 断点续传 + `tar`/`bzip2` 解包（纯 Rust crate，无外部依赖） |
| 录音 | 前端 `getUserMedia` + AudioWorklet 采集 16kHz PCM，经 Tauri command 传给 Rust；或 Rust 侧 cpal 直采（实施时择一，前端方案改动更小） |
| 事件 | Tauri event：`voice://download-progress`、`voice://asr-partial`、`voice://asr-final`、`voice://solve-confirm`、`voice://tts-state` |
| 状态 | 前端新增 Zustand `voiceStore`（模式开关、模型状态、聆听/播报状态） |
| UI | 对话页麦克风按钮 + 声波动画浮层 + solve 确认卡片；右下角全局下载列表与未就绪提示；设置页"语音模型"卡片 + "个性设置"页签 |

## 9. 验收标准

1. 首次启动后，应用**自动开始下载**缺失模型，右下角出现小型下载列表并实时显示进度；全部完成后列表自动消失；重启应用不再重复下载；
2. 断网（仅断 ModelScope）时下载自动切换备用源或明确报错；下载列表与提示浮层中均可一键重试；
3. 模型未就绪时点击语音按钮，弹出"尚未准备完毕"提示，且右下角出现重试按钮；就绪后语音功能正常可用；
4. 开启语音模式 → 说话"你好呀，今天天气不错" → 只听到语音回复，对话界面无任何新增文字；
5. 说话"帮我在项目里加一个 README" → 弹出确认卡片显示总结文本；确认后总结进入主链路并正常回复（**不朗读**），同时听到 LLM 生成的开始任务话术；点取消或语音说取消则不发送；
6. 确认卡片打开时语音说"确认 / 取消"，能被 LLM 正确判定并执行对应动作；
7. 修改个性设置为"幽默风趣"后，闲聊语气明显变化；主链路回复风格不受影响；
8. TTS 播放中再次开口说话，播放立即停止并转入聆听；
9. 全程 CPU 推理，任务管理器无 GPU 占用；短句转写 ≤ 2s；
10. 闲聊上下文"清空"后，闲聊不再记忆之前内容；重启应用后闲聊上下文为空。

## 10. 需求确认记录

以下事项已与需求方确认（2026-07-18）：

| # | 事项 | 结论 |

| 9 | 闲聊历史 | 不持久化，内存保留最近 10 轮 |
