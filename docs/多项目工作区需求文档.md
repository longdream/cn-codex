# 多项目工作区（Multi-Root Workspace）需求文档

> 版本：v0.1（草案，待需求方确认后进入实施）
> 日期：2026-07-19
> 状态：**待确认**
> 关联模块：左侧边栏（Sidebar）、右侧面板（RightPanel：文件树 / Git / 终端）、对话与项目绑定（appStore）、AI 工具执行边界（tool_executor）

---

## 1. 背景与目标

### 1.1 背景

当前 CN-Codex 已支持"项目"概念：左侧边栏可添加多个项目文件夹，每个项目下可挂多个对话。
但同一时刻**只能激活一个项目**（`currentProjectId` + 全局唯一的 `workspaceCwd`）：

- 右侧"项目"文件树只显示当前激活项目的目录；
- Git 面板只显示当前激活项目的仓库状态；
- 终端只以当前激活项目为工作目录。

用户实际开发中经常**同时面对多个项目**（例如前端仓库 + 后端仓库 + 公共组件库），
需要像 VSCode 的 Multi-Root Workspace 一样：把多个项目文件夹同时加入工作区，
文件树、Git、终端都能同时看到并操作多个项目。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 多项目并存 | 左侧可添加多个项目文件夹，**不需要切换**即可在右侧同时查看/操作 |
| 文件树多根 | 右侧"项目"页签按 VSCode 风格展示多个项目根，每个根独立折叠/刷新/搜索 |
| Git 多仓库 | Git 面板支持多个项目的仓库聚合展示与独立操作 |
| 对话绑定保持 | 现有"对话绑定项目、每轮 cwd 跟随对话"的机制不变，不破坏既有隔离性 |
| 渐进增强 | 第一阶段只做 UI 聚合层，不动后端 AI 工具的目录边界，风险可控 |

### 1.3 非目标（本版本不做）

- 不做 VSCode 意义上的"工作区文件保存/命名/共享"（`.code-workspace` 等价物）；
- 不做跨项目的全局全文搜索聚合（现有文件树内搜索仍按单个根范围）；
- 不改变对话与项目的绑定模型，不引入"一个对话同时属于多个项目"的新实体；
- 不做多窗口（每个项目一个窗口）方案。

## 2. 现状分析（关键代码位置）

| 模块 | 位置 | 现状 |
|------|------|------|
| 项目实体 | `src/stores/appStore.ts`（`Project`、`projects`、`addProject`、`selectProject`、`removeProject`） | 支持多项目列表，但激活是单选，切换即清空当前对话上下文视图 |
| 工作目录 | `src/stores/appStore.ts`（`workspaceCwd`、`resolveThreadCwd`、`syncWorkspaceForThread`） | 全局唯一；对话发送时用 `resolveThreadCwd(threadId)` 解析每轮 cwd |
| 左侧边栏 | `src/components/layout/Sidebar.tsx` | "对话 / 项目"两个页签；项目页签按项目分组列出对话；顶部有"添加项目"按钮 |
| 右侧面板 | `src/components/layout/RightPanel.tsx`（`ProjectTab`） | 从 store 读取单一 `workspaceCwd` 传给 FileTree |
| 文件树 | `src/components/layout/FileTree.tsx` | 接收单 `rootPath`，加载/搜索/上下文菜单均基于单根 |
| Git 面板 | `src/components/layout/GitPanel.tsx` | 接收单 `workspaceCwd`，所有操作基于单仓库 |
| 终端 | `src/components/layout/TerminalPanel.tsx` | 以单一 `workspaceCwd` 启动 PTY |
| Git 后端 | `src-tauri/src/git_service.rs`（`GitService::resolve_cwd`）、`src/api/git.ts` | **所有 Git API 已支持 `cwd` 参数**，天然多仓库友好 |
| 对话 cwd | `src-tauri/src/standalone.rs`（`standalone_chat` 的 `cwd` 参数）、`src-tauri/src/agent.rs`（`override_cwd` → `effective_cwd`） | 每轮对话独立 cwd，线程间隔离 |
| 工具边界 | `src-tauri/src/tool_executor/code_search_support.rs`（`resolve_search_path`） | `code_search` 强制路径必须位于**当前线程 cwd（单根）**之内 |
| 文件读写 | `src-tauri/src/tool_executor/file_op_support.rs` | `read_file`/`write_file` 相对线程 cwd 解析；绝对路径可直接使用（现状行为） |

**结论**：后端 Git 链路零改造即可支持多仓库；本次改造重心在前端 UI 聚合层 + 少量 store 结构扩展 + `code_search` 多根校验。

## 3. 需求范围

### 3.1 用户故事

1. **作为开发者**，我想把 `frontend`、`backend`、`shared-ui` 三个项目都加进来，
   在右侧文件树里同时浏览三个项目的文件，而不用来回切换项目。
2. **作为开发者**，我想在 Git 面板里同时看到三个仓库各自的变更、分支，并分别提交。
3. **作为开发者**，我想新开对话时明确选择"在哪个项目里干活"，其余项目文件仍可浏览。
4. **作为用户**，我希望删除某个项目时，不影响其他项目的文件树、Git 和对话。

### 3.2 范围内功能（编号 FR-Mx）

| 编号 | 功能 | 优先级 |
|------|------|--------|
| FR-M1 | 左侧项目列表增强：多项目并存、快速定位、空态引导 | P0 |
| FR-M2 | 文件树多根聚合展示与交互 | P0 |
| FR-M3 | Git 多仓库聚合展示与操作 | P0 |
| FR-M4 | 终端工作目录跟随所选根 | P1 |
| FR-M5 | 对话与项目的绑定、新建对话的项目选择 | P0 |
| FR-M6 | AI 工具多根访问边界（code_search 多根校验） | P1 |
| FR-M7 | 持久化与旧数据迁移 | P0 |
| FR-M8 | 国际化（zh-CN / en-US） | P0 |

## 4. 功能需求详述

### FR-M1 左侧项目列表增强（P0）

1. **添加项目**：保持现有"+"按钮（目录选择对话框，单选目录），可连续添加多个；
   已存在的目录再次添加时提示"该项目已在工作区中"，不产生重复条目（以规范化路径判重）。
2. **项目分组排序**：项目列表按"最近使用"排序（当前激活项目置顶），也可按名称排序
   （设置项，默认最近使用）。
3. **对话分组**：现有"对话"页签中的分组（回放对话、小程序对话、通用对话）保持不变；
   **项目对话分组**从"项目"页签的展开式分组，扩展为"对话"页签下也按项目分组展示
   （与通用对话分组同级，标题为项目名，可折叠），让用户不切页签也能看到项目对话。
4. **移除项目**：保持现有确认弹窗；移除仅解除绑定，不删除磁盘文件（现状行为，保持）。
5. **空态引导**：未添加任何项目时，文件树与 Git 面板显示引导（"添加项目文件夹以开始"），
   点击直接打开目录选择对话框。

### FR-M2 文件树多根聚合（P0）

1. **多根展示**：右侧"项目"页签顶部显示根列表；当工作区含 2 个及以上项目时，
   文件树按 VSCode 风格渲染为"每个项目根一个可折叠 section"：
   - section 标题 = 项目名（取目录叶子名，与现有 `Project.name` 一致）；
   - hover 显示完整路径 tooltip；
   - 每个根独立折叠/展开状态（会话内记忆即可，P1 持久化）。
   仅 1 个项目时保持现有单根布局（不增加多余层级）。
2. **根级操作**：每个根标题行提供与现有 ProjectTab 头部一致的操作：
   刷新（仅刷新该根）、在资源管理器中打开、设为"当前焦点根"（见 5.3）。
3. **搜索**：文件树内搜索按根分组返回结果（现有 `searchWorkspaceFiles` 按根分别调用后合并）；
   结果条目带所属根前缀标识（项目名徽标或颜色点）。
4. **文件操作**：右键菜单（新建/重命名/删除/预览/拖拽等）行为不变，但一律以
   "所属根"为基准路径调用现有 API（所有文件 API 均接受绝对路径，无需后端改动）。
5. **添加根**：文件树顶部提供"+"快捷入口，等价于添加项目（与左侧同步同一份 projects 列表）。
6. **异常**：某个根目录不存在（被移动/删除）时，该根 section 显示警告态
   （"目录不可访问"），不影响其他根；提供"重新选择目录"入口（更新该项目 cwd）。

### FR-M3 Git 多仓库（P0）

1. **仓库聚合**：Git 面板检测工作区内每个项目根是否为 git 仓库（`git rev-parse --is-inside-work-tree`）；
   - 非 git 仓库的项目根不进入 Git 面板（或显示"非 git 仓库"灰态，P1）；
   - git 仓库按项目分组展示。
2. **布局**（推荐方案，待确认）：
   - 面板顶部为**仓库切换条**（横向 chips：项目名 + 未提交变更数徽标）；
   - 选中某仓库后，下方展示现有 GitPanel 全部能力（变更/分支/历史/危险操作），
     所有 API 调用携带该仓库 cwd；
   - 默认选中"当前对话绑定项目"的仓库。
3. **数据加载**：仅加载当前选中仓库的 status/log/branches（避免多仓库全量刷新卡顿）；
   仓库切换条上的变更数徽标使用轻量 `git status --porcelain` 数量统计，30s 节流刷新。
4. **行为一致性**：提交、暂存、丢弃、分支操作等全部限定在选中仓库内；
   操作成功后的刷新也只刷新该仓库。
5. **兼容**：单仓库时隐藏仓库切换条，呈现与现状完全一致。

### FR-M4 终端工作目录跟随（P1）

1. 终端工具栏增加**项目根下拉**（多项目时显示），列出全部项目根；
2. 新开终端会话时以所选根为 cwd（现有 PTY `cwd` 参数支持）；
3. 默认值为"当前对话绑定项目"根；
4. 已有会话不因切换下拉而重启（保持现有"终端保持挂载"策略），仅影响新会话。

### FR-M5 对话与项目绑定（P0）

1. **绑定模型不变**：对话创建时绑定当前激活项目（`threadProjectMap`），
   发送消息时 `resolveThreadCwd(threadId)` 解析 cwd 的优先级不变：
   小程序根 > 回放根 > 所属项目 cwd > 全局 workspaceCwd。
2. **新建对话的项目选择**：
   - 从左侧某项目分组的"+"新建 → 绑定该项目；
   - 从顶部"新对话"按钮新建 → 绑定**当前焦点根**对应的项目（见 5.3）；
   - 通用对话（GENERAL）行为不变。
3. **切换对话同步焦点**：`syncWorkspaceForThread` 行为扩展为"焦点根同步"：
   打开某对话时，把该对话绑定项目设为焦点根（文件树/Git/终端默认定位到该根），
   **但不再清空多根展示**。
4. **切换项目 ≠ 切换工作区**：左侧点击项目分组头 → 设为焦点根（轻量，不重置对话区）；
   现有 `selectProject` 的"重置对话视图"重逻辑仅在新建对话场景使用
   （是否保留原行为待确认，见 §10 开放问题 2）。

### FR-M6 AI 工具多根访问边界（P1）

1. **code_search 多根校验**：`resolve_search_path` 从"单 workspace_root 校验"
   扩展为"多根校验"：路径允许落在线程 cwd 所属项目根**或**工作区内其他项目根中；
   跨根搜索时（path 指向其他项目根）按该根解析相对路径。
2. **相对路径解析**：`read_file`/`write_file`/`apply_patch`/`list_dir` 等相对路径
   仍以线程 cwd 为基准（不变）；访问其他项目需使用绝对路径或以根名开头的明确路径，
   工具输出中的路径展示保持清晰（多根时不产生歧义前缀）。
3. **不收紧现状**：`read_file`/`write_file` 对绝对路径的处理维持现状，
   本版本不新增"禁止访问工作区外路径"的白名单机制（避免破坏现有用法）；
   该项作为后续安全增强单独立项。
4. **AI 感知**：系统提示词中的 workspace 描述扩展为多根列表
   （"当前工作区包含以下项目根：…，跨项目操作请使用绝对路径"），
   让模型在多项目对话中不迷失目录。

### FR-M7 持久化与迁移（P0）

1. **项目列表**：沿用现有 `app_state.projects` 持久化，不新增存储结构；
   新增字段使用可选字段向后兼容（旧数据反序列化补默认值）。
2. **焦点根**：新增 `app_state.activeRootProjectId` 持久化（P0）；
   文件树各根折叠状态持久化（P1）。
3. **迁移**：首次启动检测旧数据（有 `currentProjectId` 无 `activeRootProjectId`），
   将 `currentProjectId` 映射为初始焦点根，全程无感。
4. **失效处理**：持久化的项目路径不存在时，标记为"失效"态（灰显 + 警告图标），
   不自动删除；用户可手动"重新选择目录"或移除。

### FR-M8 国际化（P0）

新增文案键（zh-CN / en-US 同步）：

| 键 | 中文 | English |

| `workspace.addProject` | 添加项目文件夹 | Add project folder |
| `workspace.duplicateProject` | 该项目已在工作区中 | Project is already in the workspace |

## 5. 交互设计

### 5.1 右侧"项目"页签（多根文件树）

```
┌─────────────────────────────────────┐
│ 项目          [＋] [🔄] [📂]        │   ← ＋添加根；刷新/打开作用于焦点根
├─────────────────────────────────────┤
│ ▾ frontend        ●焦点   [🔄][📂] │   ← 根 section（可折叠）
│    ├─ src/                          │
│    └─ package.json                  │
├─────────────────────────────────────┤
│ ▸ backend                   [🔄][📂] │   ← 折叠态
├─────────────────────────────────────┤
│ ▸ shared-ui                 [🔄][📂] │
└─────────────────────────────────────┘
```

### 5.2 Git 面板（多仓库）

```
┌─────────────────────────────────────┐
│ [frontend ●3] [backend ●12] [shared]│   ← 仓库切换条（●n = 未提交数）
├─────────────────────────────────────┤
│ frontend · main ↑1 ↓2               │   ← 现有 GitPanel 内容
│ ─ 变更 ────────────────             │
│  M src/App.tsx                      │
│  A src/new.ts                       │
│ [提交信息输入框.............] [提交] │
└─────────────────────────────────────┘
```

### 5.3 焦点根（Focused Root）

- "焦点根"是新引入的轻量 UI 概念 = 多根视图中的"当前默认项目"；
- 文件树刷新/打开资源管理器等头部按钮、Git 默认选中仓库、终端默认 cwd、
  新建对话的绑定项目，均取焦点根；
- 设置焦点根的方式：点击文件树根标题行 / 左侧项目分组头 / 切换对话时自动跟随。

## 6. 技术方案（概要）

### 6.1 前端 store（`appStore.ts`）

```
新增（不破坏现有字段）：
  focusedProjectId: string | null          // 焦点根 = currentProjectId 的演进
  setFocusedProject(id)                    // 轻量切换，不重置对话区
  getWorkspaceRoots(): Project[]           // 有序根列表
保留：
  projects / currentProjectId / workspaceCwd / resolveThreadCwd / syncWorkspaceForThread
  （currentProjectId 与 focusedProjectId 合并迁移：见 6.3）
```

- `workspaceCwd` 保留为"焦点根的 cwd"，作为所有未显式传 cwd 的旧调用点的兜底，
  避免一次性改动全部消费方。

### 6.2 组件改造

| 组件 | 改造 |
|------|------|
| `Sidebar.tsx` | 对话页签增加按项目分组（复用 `ChatGroupSection`）；项目分组头点击 → 设焦点 |
| `RightPanel.tsx` | `ProjectTab` 多根化：`projects.length > 1` 时渲染多个根 section，内部复用 `FileTree` |
| `FileTree.tsx` | 无需结构改造（仍单根），由父级多实例化并传入各自 `rootPath`；搜索结果带根标识 |
| `GitPanel.tsx` | 增加仓库切换条；内部 `workspaceCwd` 来源改为选中仓库 cwd；API 调用不变 |
| `TerminalPanel.tsx` | 增加 cwd 下拉（P1） |
| 新增 `WorkspaceRootSection.tsx` | 根 section 通用容器（标题/操作/警告态/折叠） |

### 6.3 后端改造（少量）

| 位置 | 改造 |
|------|------|
| `tool_executor/code_search_support.rs` | `resolve_search_path` 接受根集合 `&[PathBuf]`；遍历校验 + 按命中根解析相对路径 |
| `agent.rs`（system prompt 构建） | workspace 描述输出多根列表 |
| `standalone.rs` | 新增 `workspace_roots` 查询命令（返回项目根列表及 is_git_repo 标记），供 Git 面板探测 |

其余 Git / 文件 / 终端链路**零后端改动**（API 均已支持显式 cwd/绝对路径）。

### 6.4 迁移与兼容

- 单项目用户：所有界面与现状一致（不显示根 section 层级、不显示仓库切换条）；
- 旧持久化数据：`currentProjectId` → `focusedProjectId` 自动迁移；
- 对话 cwd 链路：不受影响，回归测试覆盖即可。

## 7. 边界与异常场景

| 场景 | 预期行为 |
|------|----------|
| 添加已存在的项目目录 | 提示已存在，不重复添加（路径规范化判重，含大小写/分隔符差异） |
| 项目目录被外部删除/移动 | 该根显示"目录不可访问"警告态；Git 探测跳过；可"重新选择目录" |
| 添加的项目是另一个项目的子目录 | 允许（VSCode 同样允许）；文件树各自独立渲染，不做去重 |
| 项目根不是 git 仓库 | 不进入 Git 仓库切换条（P1 显示灰态说明） |
| 移除当前焦点根对应项目 | 焦点自动落到剩余第一个项目；若项目下有对话，对话保留但解绑（现状行为） |
| 多根同时进行 AI 编辑 | 对话每轮 cwd 仍锁定绑定项目；跨项目写入需绝对路径（工具输出可见路径） |
| 路径含中文/空格/UNC 网络路径 | 现有 normalize 逻辑保持；Git 探测对 UNC 路径允许失败并警告 |
| 对话运行中切换焦点根 | 不打断流式输出；不影响本轮 cwd（cwd 已在发送时固化） |

## 8. 验收标准

1. 添加 3 个项目后，右侧"项目"页签可见 3 个可折叠根，各自可浏览/搜索/右键操作；
2. Git 面板可在 3 个仓库间切换，分别完成 stage → commit，互不串扰；
3. 从项目 A 分组新建对话后发送消息，后端收到 cwd = 项目 A；切到项目 B 对话发送，cwd = 项目 B（日志验证）；
4. 单项目场景下，文件树/Git/终端界面与改造前一致（回归）；
5. 旧版本升级后首次启动，焦点根 = 上次激活项目，无数据丢失；
6. 移除某个项目后，其余根、其余项目对话、Git 均正常；
7. `zh-CN` / `en-US` 下所有新增文案完整无缺键；
8. `code_search` 在多根工作区内任一根下均可用，指向工作区外的路径仍被拒绝。
